### 0.3 明确作废的中间方案

不采用“开启自动追踪时把最老的旧任务补到三个”；不采用“持续维持三个任务，取消一个就补一个”；不采用“关闭自动追踪就清空已追踪任务”；不把新设置放进「外观」页。

不设计“弹窗出现把追踪向下移”“弹窗消失再移回”“两个 HUD 共享可用区域”“同侧自动重新排布”。之前关于这种跳动的讨论是假设方案的风险，**不是已经确认的现有 Bug**，不得把它写成待修问题，也不得为了修它引入新的协调系统。

### 0.4 不在本版范围

不重做任务界面的整体视觉，不新增 HUD 自由拖动、坐标输入、锚点矩阵、可配置追踪数量或可配置单任务像素额度；不新增任务排序／优先级编辑器、自动任务推荐、依赖求解器、Group Runtime、旧 Namespace 兼容或旧格式迁移工具。

不重写 Story／Session／Task 的执行模型、结算机制、身份协议、奖励或任务进度。普通列表平滑滚动不等于重做画布缩放、节点拖动和列表拖动排序。

## 3. WP-A：任务追踪选择与逐任务显示额度

### 3.1 自动追踪：只处理新接任务

设置显示名称为「新任务默认开启追踪」，默认开启。它只控制新任务进入追踪集合的默认行为，不是整个 HUD 的总显示开关，也不取代逐任务按钮。

| 事件 | 要求 |
|---|---|
| 开关开启，收到一个真正新接任务，当前不足 3 个 | 自动加入这个新任务。 |
| 开关开启，当前已经追踪 3 个，收到新任务 | 不加入；不取消、挤掉、重排任何已选任务。 |
| 开关关闭，收到新任务 | 不自动追踪；仍可在任务界面手动追踪。 |
| 从关闭改为开启 | 仅保存设置；不扫描旧任务补位。 |
| 从开启改为关闭 | 仅停止之后自动加入；当前已选任务保持。 |
| 玩家取消某任务追踪 | 该任务退出；不立即重新加入，不从旧任务中补位。 |
| 已追踪任务完成／失效 | 按现有任务实例生命周期移出选择；不从旧任务中补位。 |
| 打开／关闭任务窗口或设置、重新进入服务器 | 不当成新接任务；恢复该上下文合法的既有选择。 |
| 相同通知重发、重复快照、重连初始同步 | 不重复自动加入，不复活手动取消的追踪。 |
| 相同任务定义在以后重新接取，产生新实例 | 视为新任务实例；按当时开关与剩余额度处理。 |

**明确不做：**最老任务自动补满、持续维护三个、满额自动淘汰、关闭开关清空选择、把当前未完成任务列表全当成新任务。

### 3.2 身份与事件边界

沿用当前任务实例身份和服务器／本地存档上下文；基线选择键包含任务标识与 `activation`。[S04] 不用任务名称判同一任务，不让不同存档、不同服务器或新旧任务实例共用一个选择结果。

工程要求：先核对现有通知 revision／event identity 的消费路径，再把开关接到“首次接受新接取通知”的位置。**开关关闭或追踪已满时的通知也算已消费**，不能等设置改变或空位出现后重放它们。优先复用现有事件去重／快照边界，不为了这个简单功能创建长期任务调度器。

一次有效更新可能包含多个新接任务；按服务端提供的确定顺序处理。若该顺序本身无定义，使用真实接取顺序建立稳定次序并测试，不能按显示名称或 HashMap 遍历取前三个。这仍然是处理本批新事件，不是扫描历史任务。

手动「追踪／取消追踪」继续使用当前任务界面的按钮和 0／3—3／3 计数，不新增第二套手动控制。满额提示保持轻量，不自动替用户决定取消哪个。

### 3.3 从整体限高改为逐任务正文额度

用户选择的任务集合和 HUD 显示内容是不同层：**布局不得修改选择集合，且不得把后续整个任务省略。** 对每个被选择且仍有效的任务，至少保留可辨识的任务名称及所属故事上下文；压缩的是它自己的正文，不是该任务条目的存在。

继续沿用现有故事／任务／目标视觉层级、边框、字体和物品图标样式。只调整高度分配与溢出显示，不借机把 HUD 改成另一种设计。

每个任务有独立正文额度，按实际折行后的逻辑像素高度核算，包含进度行、物品图标、行距和溢出提示；不能只按原始字符数量或目标数量计算。中文、长名称、100%／125%／150% 字号、含图标目标都必须进入同一测量结果。

允许因屏幕高度、GUI Scale、文字缩放以及当前追踪任务数调整额度；**不读取任务弹窗的位置、数量、高度、动画或可见性**。同一显示条件下使用一致的单任务上限，不能让第一个长任务贪占预算导致第二、第三个任务消失。

### 3.4 推荐的布局计算步骤（工程建议）

1. 先收集实际选中的最多 3 个任务，为全部任务名称、故事标题、边框和间距预留最小空间。
2. 在该 HUD 自己的屏幕安全范围内，计算每个任务可用的正文上限；不再使用“累计超过屏幕三分之一就停止添加任务”的规则。
3. 每个任务独立排版。放不下的正文在完整行／完整图标块边界停止，保留一行轻量溢出标记。
4. 正文为空或很短时自然收缩，不为了等高留下大片空白；也不把节省的空间无限灌给第一个任务。
5. 受支持的窄窗口／大字号下优先减少正文，不能把已选任务整条替换为「另有 N 个任务」。所有任务条目都必须在实际支持的屏幕范围内可辨识。

具体常规高度由实现时的截图对照和实机阅读确定，在验收记录中写明最终参数。不添加玩家可调的像素预算、每任务长度设置或任意可配置数量。

### 3.5 溢出标记

使用图1需求中的感叹号作为轻量标记，推荐文案为「! 部分内容已省略」。它表示正文未全部显示，**不是任务错误、结算失败或身份冲突**，不得套用故事包冲突的红色警告视觉。

标记放在该任务块底部且计入高度；不能半行文字和半个物品图标被硬切掉。可准确计算完整未显示目标数时，可以在标记后补充数量，但不能把部分截断的目标错误计为完全隐藏目标。

追踪 HUD 不新增鼠标交互、悬浮窗口或滚轮阅读模式；完整目标仍在已有任务界面查看。文本截断须保留有效 Unicode 字符边界和必要格式状态，不出现半个字符或格式码泄漏。

### 3.6 布局稳定性

快照／选择／字体／字号／窗口／左右设置改变时再使布局缓存失效；不能每帧重新解析全部任务资源。重新测量可以改变追踪本身的高度，但与任务弹窗无关。

原有计分板处理若保留，只能是追踪 HUD 自己既有的边界逻辑；新增左侧模式不能仍无条件扣除右侧计分板宽度。不要顺势新增第三方 HUD 自动探测或通用避让系统。

## 4. WP-B：独立「任务」设置页与背包键关闭

### 4.1 页面结构

```text
设置
外观 | 文本 | 声音 | 任务

任务追踪
[✓] 新任务默认开启追踪
显示位置   [左侧] [右侧]

任务弹窗
显示位置   [左侧] [右侧]
```

只新增这三个用户设置。两个位置选项独立保存，允许左／左、左／右、右／左、右／右四种组合。任务页属于普通玩家的本地设置，不需要 OP 权限；不得与 O 键的 OP 故事包管理器混淆。

保持现有设置窗口的主题、拖动／缩放、留白和按钮风格；不要改坏现有「外观／文本／声音」页面，也不要把任务窗口本身加上一排额外设置按钮。

### 4.2 不得只改标签字符串

`GuiDialogueSettings` 当前多处使用“三页”的硬编码：标签数组、循环、宽度分配、点击索引、`tab` 分支、页面内容高度和 slider 命中。[S05] 增加第四页必须同时处理这些路径。

工程上让页数来自同一份标签定义，避免第四个标签被挤出窗口或点击后仍走文本／声音分支。左右位置是二选一，不要直接套用现有三个选项的等分宽度而只显示其中两个。

新页内容超出可见区域时使用 WP-D 的平滑滚动；绘制、控件命中和滚动范围一致。切页时同步重置／恢复该页合法滚动状态，不带着上一页动画把新页滑到空白。

### 4.3 设置存储

在现有客户端偏好链上增加自动追踪与两个 side 字段；沿用 `PlayerUiPreferences` 和现有设置存储，不新建云端配置、服务器命令或额外身份系统。[S06]

偏好命名须区分“新任务自动追踪”与“对话自动播放”，不能复用现有 `automatic` 字段造成串设置。side 值使用明确的 Left／Right 语义；缺少新增设置键时使用本版默认值，非法值回到安全默认值，不破坏其他偏好。

位置／自动追踪偏好沿用现有客户端展示设置范围；具体任务的手动追踪选择继续按现有服务器／存档上下文隔离。显示设置不写入 `.dgrs`、`.dgrs.g` 或任务运行状态。

「恢复默认」纳入这三项默认值，但不得清空已经追踪的任务，也不得把旧任务补到三个。只是改偏好，不是假造一次任务接取事件。

### 4.4 背包键关闭

设置窗口支持玩家当前配置的背包键，不写死字母 E；保留 Escape 和设置快捷键的关闭能力。读取实际 KeyBinding，未绑定键不得把普通字符输入当关闭操作。[S05]

如果背包键被绑定到鼠标按键，也应通过现有按键约定识别；先关闭并消费事件，不能继续点击同位置的设置控件。键盘关闭同样不能穿透到世界并立即打开背包，不能因按键残留又重开设置。

所有关闭路径统一经过现有关闭／保存生命周期，结束滑条拖动和窗口几何交互，保存最后有效值。若从对话打开设置，返回时保持原对话实例和位置，不重新播放整段或代替玩家发送继续。

## 6. WP-D：普通滚轮滚动统一为平滑内容位移

### 6.1 修复目标

本项不是淡入淡出或“看起来刷新了”，而是让用户实际看到文本、行背景和图标连续滑动。图4的任务列表不能继续通过改变首行索引，直接把一批文字替换成下一批。[S08]

游戏端优先复用已有 `SmoothScroll`，必要时做最小泛化。基线组件已经有当前位置、目标位置、按经过时间推进的缓动及边界夹取；这不要求新建动画框架。[S09]

### 6.2 统一交互合同

滚轮只更新目标偏移；每帧依据经过时间推进当前位置。连续滚动累计到最新目标，反向滚动从当前位置自然转向，不为每个滚轮刻度排队播放动画。不因帧率不同改变滚动距离或手感。

文字、背景、选中标记、图标和滚动条使用同一个当前偏移。滚动区有严格裁切，边缘可见的部分行应随内容滑出；不得只把文字移动而留着旧选中框。

点击、悬停、Tooltip、详情按钮、图标展开、任务选择和目录折叠命中，都必须基于**屏幕当前显示的偏移**，不能使用尚未到达的目标位置。节点或条目移出裁切区后不能继续被点击。

只有鼠标所在滚动区域消费滚轮。嵌套列表、弹出候选框优先消费自己的滚轮；窗口外不能驱动列表。滑条调值、画布缩放和主动翻页保持各自操作语义，不误归入普通列表滚动。

### 6.3 行高、详情及分页

`SmoothScroll.rowAt()` 的 20 像素假设只适用于对应固定行高列表。[S09] 任务界面行高会随布局和字号变化；必须传入实际行高或用真实布局边界计算索引，不能只接上 `wheel()` 就宣称完成。

任务详情含文本和物品预览等不同高度的块，要用实际像素位置；列表／详情各有自己的滚动状态。原来的 `DetailBlock.top/bottom`、物品点击范围等需要随显示偏移同步。

保持分页作为数据传输机制而非突然替换一整页。接近底部触发已有增量请求时防止重复请求；数据返回后追加并更新范围，不每帧轮询，不把还未返回的数据区冒充空白内容。网络失败和重试不能让滚动状态永久漂移。

列表过滤、切换已完成／进行中、故事折叠、字号改变和窗口缩放后，重新约束 position 与 target。窗口初次打开或用户明确跳到首／尾可以直接定位，不从 0 播放一段很长的假滚动。

### 6.4 本版自查范围

| 区域 | 必查项目 |
|---|---|
| 游戏任务界面 | 任务／故事目录列表、目标详情、已完成历史、详情增量加载。 |

### 6.5 WPF 与已有动画边界

Studio 使用适合 WPF 的像素级滚动／轻量行为实现相同手感，不跨端搬 Java 类。保留虚拟化，不要为了动画把整个资源库一次性建立成全部 Visual；避免全局关闭 `CanContentScroll` 或虚拟化造成新的性能退化。

保留用户已认可的 220ms 折叠和相邻项让位式排序规范；滚轮内容移动不是另一次折叠、重排序或整个节点缩放。尊重系统动画设置，系统关闭动画时可以即时滚动，但命中和裁切仍必须正确。[S02]

把本轮确认的普通滚轮标准和检查要求补到已有 UI 规范／相关 skill 中，未来新增页面默认复用，不再每个页面单写跳行逻辑。不要另造大型治理系统或多套重复规范。

## 7. WP-E：【与】【或】自定义 Logic 输入数量

### 7.1 产品语义

三种图 Story、Session、Task 中的【与】【或】均支持 2 个及以上 Logic 输入。默认创建两个，输出仍为一个 Logic 输出；【非】不变。

- 【与】：所有输入为 True 时输出 True。
- 【或】：任意输入为 True 时输出 True。
- 已存在但未接线的 Logic 输入按现有语义视为 False，不能在【与】中被跳过或改成 True。

不为作者新增“最大输入数量”设置；继续保留项目现有的正常数据和资源安全限制，不为实现增减放开整个图的校验。

### 7.2 双入口的紧凑编辑

在节点自身属性区和右侧 Inspect 都提供同一套输入编辑，复用台词／选择节点已经熟悉的增减交互风格，但不复制其业务模型。

```text
逻辑输入（3）  [+]
输入 1          [-]
输入 2          [-]
输入 3          [-]
```

输入只有一项简单名称时使用紧凑行，不把每个输入包成一张大卡片。无需为了增减数量添加作者必须填写的 ID、优先级、数据类型或复杂端口表单。

增加时生成稳定内部 ID，名称自动产生；删除按钮明确针对该行。数量大于 2 时允许删除任意可编辑输入；仅剩 2 个时禁用删除，不设置“最初两个端口永久不可删”的额外规则。

### 7.3 图编辑合同

走已有动态端口能力及图编辑事务；基线已经声明 AND／OR 的 MinimumCount=2。[S11] 不是把多个二输入节点藏在后台自动套娃，也不将 AND／OR 替换为另一种节点类型。

增加或删除只修改选中节点的对应动态输入；固定输出、其他输入 ID 和其他节点保持。新增与删除都可作为一次 Undo／Redo 操作；删除已接线输入时，同一次操作处理它的关联线，并按现有删除确认偏好执行，不另加反复打断的新流程。

保留其他端口连线身份，不通过“删掉整个节点再新建”实现。节点高度变化只更新必要几何，不引起整图闪烁、连接重置或正在操作的其他节点失焦。

### 7.4 运行与全链验证

虽然已核对的 Task 求值器支持遍历全部输入，[S13] 施工仍必须检查 Story／Session 的求值、校验、序列化、复制、保存重开、导出和 Runtime 加载。不能只凭 Studio 画出了第三个菱形就认为完成。

至少验证 2、3、8 输入以及未连接输入；对三输入 AND／OR 穷举真假组合；故意制造不足两个输入的损坏数据，校验必须给出准确错误。

多输入只是逻辑组合能力，不改变 Task 多结算节点、结算优先级或一次实例只提交一个结果的规则；不重新恢复唯一结算节点，也不新增 Task Flow 连线。

## 8. WP-F：拖放错误提示生命周期与准确预判

### 8.1 问题定位

图7对应的文本为「角色资源只能拖到 Start 的角色交互、会话台词说话者或任务角色目标。」它由参数拖放失败写入，不是节点的持久校验状态。[S14]

现有提示覆盖层只根据 `HasParameterDropMessage` 显隐，没有在这条反馈链上提供完整的自动结束机制；不能把它留到用户重启 Studio 才消失。

### 8.2 短时反馈

采用约 3 秒的局部提示。新提示替换旧提示并重新计时；即使两次提示文字相同，也按新的一次操作更新生命周期。切换 Story／Session／Task 图、关闭工作区或销毁 ViewModel 时立即清理。

定时器／异步回调绑定本次提示的版本或取消令牌；上一条提示的过期回调不能清掉后来出现的提示，更不能在已关闭窗口中复活提示。释放事件和定时任务，不造成订阅泄漏。

拖拽预览、幽灵节点和排序标记在手势结束立即清理；错误消息应保留可阅读的短时长，不能在 `DoDragDrop` 的 finally 中一并立即抹掉。保持提示不挡住画布正常操作，不为它新增模态确认框。

这条反馈和真正的保存／校验错误要分开：不能把 Problems 面板中的有效错误也在 3 秒后自动清除。现有成功拖放反馈若保留，也应短时结束，不常驻。

### 8.3 DragOver 与 Drop 使用相同接受条件

鼠标下“有节点”不等于角色／物品可以放入该节点。预览必须检查实际资源类型、目标字段、当前可写性与候选范围；Drop 重新验证同一规则，不能预览为可放置、落下才套另一个更严格条件。[S14]

复用现有选择框拖放能力，优先精确命中用户指向的字段。多条启动条件、奖励和包含多个资源参数的节点必须只修改被命中的那条；不默认写第一条。类型错误或目标不明确时，不继续向父级冒泡并误改其他属性。[S02]

对于原有整节点快捷拖放，只保留既有明确、唯一的合法目标；多个候选字段时不要猜、不要新增选择向导。针对提交物品等现有节点，以实际参数 schema 和选择框能力核对，不继续使用已经落后的硬编码允许列表。

重复放入已经选中的同一资源可以是无副作用的成功／无变化，不应制造长期错误。取消拖拽、移出画布、Esc、窗口失焦都要退出预览，不改变数据。

提示文案使用现有中文节点名，例如【开始】，而不是混入英文 Start；文案清理不能替代上述生命周期和命中修复。

## 9. WP-G：两套独立 HUD 的左右位置与通知层级

### 9.1 不可破坏的独立性

任务追踪和任务弹窗是两个独立的 UI：各自读取自己的 side、计算自己的位置、尺寸和动画，分别维护自己的内容。

**禁止新增任何跨组件布局依赖：**任务弹窗出现／消失不得移动、压缩、隐藏、裁切或重排追踪；追踪任务数变化不得移动、缩小或延迟通知。不能共享一个“剩余高度”或“占用区域”来相互挤让，也不能通过事件通知对方补偿位置。

设置中只有两个独立的左右选择，不提供“同侧协调”“自动避免遮挡”之类新选项。选在同侧时也照各自规则绘制；视觉叠加由绘制顺序处理，不做相互交互。

### 9.2 左右位置与动画

右侧模式保持既有边距和基本布局；左侧模式用对应边缘定位。追踪使用自己的水平定位；不镜像文字阅读方向、物品图标或任务内容顺序。

通知在右侧从右边进入、向右边退出；在左侧从左边进入、向左边退出。不允许只改静止坐标，动画仍横穿整个屏幕。复用现有通知的进入、停留、退出和队列补位节奏。[S16]

设置改侧只改变对应 HUD 的锚点／动画方向，不伪造通知、重播任务接受事件、清空通知队列或重新开始任务。活动通知的剩余生命周期保持；可按当前动画进度投影到新侧，保证下一帧落在正确边缘且不闪烁。

通知内部多张卡片已有的上下补位是该组件自己的行为，可以保留；它与常驻追踪 UI 没有关系。

### 9.3 DGR 自有层级

当前桥接先画通知、再画追踪，因此 DGR 自己都未保证通知位于最后。[S15] 先整理已有绘制入口，在需要显示通知的 HUD 场景中让通知最后绘制，不增加第二套通知副本。

区分游戏 HUD 与 GUI 打开后的绘制阶段。当前已有 overlay 和 GUI post 两条路径，必须保证同一可见层中不出现重复叠画导致变深、闪烁、文字重影；不能把生命周期推进次数错误绑定为每调用一次 draw 就推进一份固定时长。

为每个绘制入口保存并恢复必要的矩阵、裁切、混合、颜色和深度等状态。不能依赖前一个 Mod 的残留状态，也不能为“压住别人”污染后续渲染或破坏原版 UI。

### 9.4 第三方小地图的验证边界

产品目标是解决图8的小地图遮挡任务弹窗。施工首先记录目标小地图 Mod 名称、版本、Forge／客户端组合和相关显示设置，找到其实际绘制入口。**不得凭截图猜 Mod 名称并写成已验证兼容。**

Forge/FML 的事件调用优先级与屏幕叠放顺序不是同一个概念。不能机械把处理器设成 `HIGHEST` 就宣布“画在最上层”；需按实际事件阶段和调用顺序验证。在合适末端绘制通知，优先局部调整既有桥接，不新增通用 HUD 管理平台或任意核心渲染注入。

验收承诺是：DGR 自有层级正确，并在记录的目标 Mod 环境中确实不再被覆盖。不得宣称能绝对盖过任意未知 Mod 在任意更晚阶段的绘制。目标环境尚未取得时，可以继续实现和其他测试，但该兼容项必须标记待实测，不能填 PASS。

保持既有对话、标题、F1 隐藏 HUD 等场景的显示边界；本项不是要求任务通知永久覆盖所有全屏菜单、加载画面和交互控件。

## 10. 共同工程约束与回归边界

### 10.1 继承 0.3.3.6，不倒退

本版不改不可变 Story UID、Studio 自动管理的资源身份、自动 Story Group、`.dgrs`／`.dgrs.g` 容器、冲突处理或 Reference 语义。不得以这次 UI 修复为由恢复 Namespace、Full ID 输入、UID 重新生成或兼容旧 Namespace 的 fallback。

不为了当前版本偏好新增键而重做身份／数据迁移。旧源码或旧计划中与当前决定冲突的要求，不得再变成活动主链。

### 10.2 任务状态与展示分离

### 10.3 表现与性能

## 13. 端到端验收样例

### E2E-A：手动优先与超长任务

使用真实 Studio 内容建立至少四个任务：第一个包含多段长目标，第二个包含物品图标与数量，第三个来自另一 Story，第四个作为之后的新任务。先让自动追踪加入前三个，确认三个条目均显示；手动取消其中一个，旧任务不补位；关闭开关再接新任务，不加入；重新打开开关，仍不补之前接到的旧任务。之后真正再次接取一个新实例，才按空位加入。重连后选择正确恢复。

### E2E-B：左右位置与目标小地图

保留图8的小地图环境，分别执行四种左右组合。触发接取、结构更新、完成／失败通知；观察通知进入、排队、补位和退出。过程中改变追踪的任务数量，证明通知不变；通知队列变化时证明追踪不变。录下存在小地图遮挡区域时弹窗实际在上层的证据。

### E2E-C：平滑滚动中立即点击

准备足够长的任务目录及详情；连续滚动后在动画尚未结束时点一个任务，再点物品预览／候选入口。验证实际选中和屏幕看到的是同一对象。覆盖目录折叠、已完成历史分页、缩放字体和窗口。再执行滚动检查表中的其他窗口，不能只拿任务界面的结果代替全项自查。

### E2E-D：三图多输入逻辑

在 Story／Session／Task 各建立三输入以上的 AND／OR，连接真实逻辑来源，增删已连接输入并撤销。保存重开后，由0337 Studio正式导出单Story包和一个组容器，加载到 Runtime 验证真假传播与任务最终结果。不要只在内存构造图后断言端口数量。

### E2E-E：Studio 定点修复与关闭链

触发图7同类非法拖放，观察消息自然消失；消息尚在时切图，再等待，不能复活。对正确的第二个资源选择框拖入资源，保存重开确认赋值准确。检查Minecraft占位页已删但导出功能仍可用。在Minecraft对话中打开设置，改任务设置后用改绑背包键关闭，原对话继续且不会打开背包。
