## 2. UI 强制规范与视觉验收

### 2.1 施工前必须阅读的现有规范

修改前阅读仓库：

- `AGENTS.md`
- `.agents/skills/studio-node-ui/SKILL.md`
- `studio/src/DarkGreyRPG.Studio/Views/Graph/RewardEntriesEditor.xaml`
- `studio/src/DarkGreyRPG.Studio/Views/Graph/LinePagesEditor.xaml`
- `studio/src/DarkGreyRPG.Studio/Views/Graph/AnimatedLinePageBody.cs`
- `studio/src/DarkGreyRPG.Studio/Views/Graph/AuthoringText.cs`

项目现有 UI skill 已明确多模块卡片、文字层级、资源拖放和折叠动画规范。本版不是重新设计主题，而是**严格沿用这些已认可的设计语言**。[S2][S3]

### 2.2 功能区必须一眼可辨

每个独立的多字段功能模块使用一张卡片。用户无需阅读源码或逐个尝试按钮，就应看懂：

- 这一块是什么功能。
- 哪些字段属于这一块。
- 当前功能是否启用、是否有错误。
- `+`、`−`、删除、选择资源等操作影响哪一项。

**采用卡片的对象：**重复设置、每条多字段启动条件、每句台词、Debug 玩家信息与状态详情、动态内容选择器内需要填写对象的设置区。

**不要机械卡片化：**一个单独的字段不单独套卡片；简单选项列表不变成巨型卡片列表；不借此改造本版无关的 Choice、Settlement、Screen 布局。

卡片结构必须包含标题、可见边界、合理内边距和卡片间距。禁止将十几个 Label/TextBox 直接纵向堆叠在同一背景上。

### 2.3 视觉参数沿用项目既有值

| 元素 | 规范 |
| --- | --- |
| 卡片圆角 | 沿用现有参考：`4 DIP` |
| 卡片内边距 | 沿用现有参考：`8 DIP` |
| 卡片间距 | 沿用现有参考：`10 DIP` |
| 卡片背景/边框 | 主题卡片背景、可见灰色边框；优先引用现有资源，不在每页重新硬编码 |
| 字段名、已输入正文 | 正常正文样式；可读，不伪装成说明文字 |
| 帮助文字 | `AuthoringText.IsHelp`；现有 `11 DIP`、正常字重、自动换行 |
| Placeholder | 复用现有机制；只在空输入显示，不写进数据 |
| 报错 | 图标或明确文字 + 错误颜色；不可只靠颜色区分 |
| 动态内容块 | 比正文有明确边界，使用主题适配的轻强调底色；不能亮得压过正文 |
| 功能按钮 | 文字可读、作用明确；不使用难以理解的纯符号作为唯一入口 |

现有 skill 的深色说明色为 `#B8B8B8`、占位色为 `#909090`，浅色对应 `#666666` / `#888888`。应通过现有语义样式复用这些规则，不把所有文字改白，也不把深色固定值搬到浅色主题。[S3]

**不要新增深海军蓝主题、渐变大底、发光边框或装饰性大图标。**美观来自统一层级、对齐、留白和状态反馈，不来自增加装饰。

### 2.4 节点内与 Inspector 的一致性

两处必须保持：字段、顺序、名称、默认值、资源候选、单位、说明、校验和错误处理一致。

- 在节点内改值，Inspector 对应内容同步；反向亦然。
- 两处不维护各自独立的业务状态；同一次编辑只能写一次 canonical 数据。
- 两处使用同一 Graph 历史；不能一次操作产生两次 Undo。
- 共享引用的改动遵循现有共享规则；外部只读引用仍不可写。
- 新抽取的选择控件必须保留 `ResourceSelectorDrop.Kind` 拖放能力：只修改实际命中的字段，不误改第一项。
- 控件中的点击、输入、滚动、Enter、Backspace、删除动态块，不得冒泡成画布拖动、删除节点或删线。

建议复用内容组件，而非继续复制两套 XAML 后靠人工保持一致。只在受影响区域抽取共用组件，不进行全项目 UI 架构重写。

### 2.5 控制高度：折叠，不删功能

重复设置使用**一张可折叠卡片**。展开可编辑完整参数，收起显示规则摘要。复杂规则不强行横挤在一行；可在狭窄区域自然排成两到三行。

不要为了让截图看起来短，做出以下实现：

- 节点只能读摘要，参数必须去 Inspector 改。
- 固定一个过低的高度把参数裁掉。
- 每个字段嵌套一层 Expander。
- 宽度不够时把下拉箭头、单位、时间数字压到不可辨认。
- 在节点内部制造横向滚动才能访问的设置。

重复设置的复杂度通过“仅显示当前模式字段”控制。启动条件继续按卡片组织；本版不借机更改启动条件触发语义或大改所有条件卡片交互。

### 2.6 折叠动画必须复用已有标准

按现有 `studio-node-ui` 规范：[S3]

- 展开、收起均为 **220 ms，CubicEase / EaseInOut**。
- 使用自然高度测量、显示高度和裁切；不能整体缩放挤压文字及输入框。
- 动画中再次点击，从当前进度平滑反向，不排队、不跳回起点。
- 展开结束恢复自然高度；收起不残留正文占位和可点击的隐藏控件。
- 初始化、卸载直接同步最终状态；尊重系统关闭动画的设置。
- 保留现有连线对象和输入命中区，只更新必要端点几何；禁止逐帧销毁重建全图连线。

折叠开关只改变编辑器展示，不修改 DGRS 语义、不推进 Runtime、不污染业务 Undo 历史。

### 2.7 实际窗口约束

Studio 必须在现有最窄合法 Inspector/节点宽度及正常宽度下可用。至少人工检查 Windows 100%、125%、150% 缩放；在实际支持的浅/深主题下检查，不能只交一张开发机全屏截图。

时间输入优先采用自然换行的字段组合，例如：

```text
时间规则   [ 每周 v ]
星期       [ 星期一 v ]
时间       [ 12 : 00 ]
```

而不是强制把四个小选择器塞进 230 DIP 左右的区域。宽度较充裕时可以合并布局，但不得改变操作顺序。

### 2.8 UI 拒收条件

以下任意一项成立，即使自动测试全绿也不得宣称交付：

- 功能区界限模糊，按钮归属不清。
- 不同主题出现黑字黑底、浅灰白底不可读、错误只靠颜色。
- 关键参数只能在 Inspector 修改。
- 展开/收起导致连线闪烁、文字变形、焦点丢失或明显抖动。
- 插入动态内容后普通输入、IME、Undo/Redo 退化。
- Debug 用原始 JSON/NBT/Java Map 代替正式状态 UI。
- 小窗口或缩放后字段、错误、主操作被裁掉。
- 只检查 XAML 或截图，没有在交付 EXE 与真实 Minecraft 中操作。

## 3. 模块 A：【台词】节点连续编辑

### 3.1 目标与当前基础

[确认] 一个【台词】节点包含有序 `pages[]`；一句对应一个作者页面，单句正文不接受显式换行。键盘操作只优化编辑，不改变 Session Runtime 的逐页执行语义。

[基线] 当前 `AddLinePage()` 在末尾追加 Page；`LinePagesEditor.Add_OnClick` 已通过新 Page ID 选择、滚入视野并聚焦。新增、删除和页面属性变化经 `_host.SetNodeProperty(..., "pages", ...)` 提交。[S4][S5]

因此，**不能把 Enter 简单绑定到现有尾部追加方法**。须支持在当前 Page 后插入，同时沿用现有命令/校验/历史。

### 3.2 Enter 行为

满足“正文编辑器有焦点、不是 IME 提交、不是选择器确认等子交互”时，普通 Enter：

1. 正确处理当前文本草稿，不能丢失尚未 LostFocus 的输入。
2. 在当前 Page 后插入新 Page，使用现有 `+` 的页面默认值。
3. 不切开光标后的文字，不自动移动原句后半段，不复制原句语音等设置。
4. 展开并滚动新句到可见区域，聚焦新句正文，光标置开头。
5. 消费此次按键，不在正文写入 CR/LF，不触发别的默认按钮。

```text
原来：A → B（正在编辑）→ C
Enter 后：A → B → 新句（焦点）→ C
```

Enter 在原句中间也只是新增下一句，不是文字处理软件的拆段。原有 `+` 的行为不需要因此改为插入。

### 3.3 空句 Backspace 行为

仅在以下条件全部满足时执行结构删除：

```text
本次按键开始前，当前正文内容已经完全为空
AND 当前 pages.Count > 1
AND 当前资源可编辑
AND 不是 IME 编辑或子控件快捷键
```

- 删除当前 Page，而不是当前多选集合。
- 有上一句：聚焦上一句正文末尾。
- 当前在首位但仍有其他句：删除后聚焦新的首句开头。
- 仅剩一句：不结构删除，不删除整个节点。
- 正文仍有字符时仅执行普通退格；本次删掉最后一个字符后，**不在同一个按键里继续删 Page**。
- 空格也是内容，不用 `Trim()` 偷偷把有空格的句子判空。
- 含动态内容块的正文不是空句。删掉最后一个动态块后，也要等下一次退格才允许删除 Page。
- 长按 Backspace 不得连带穿透删除相邻多句；快捷结构删除要防按键自动重复。
- 本版快捷键为 **Backspace**；不把实体 `Delete` 键擅自改成同样的删句动作。

### 3.4 最后一项数量保护——最高风险红线

> **保护的是“只剩一项”这个数量条件，不是任何 Page 身份，也不是索引 0。**

禁止使用 `first_page_id`、`is_initial_page`、`index == 0` 等判断是否可通过快捷键删除。

验收必须包含：

```text
创建 A / B / C
将最早创建的 A 移到末尾：B / C / A
清空并删除 A：必须成功
清空并删除当前第一项 B：必须成功，焦点进入 C
只剩 C：Backspace 不再删除 C
再新增 D：C 重新可以被删除
```

此限制针对新快捷删除。不要未经授权改变现有显式 `−`、多选删除和删除整个节点的语义，更不能把一个 Page 做成永久不可删除对象。

### 3.5 Undo/Redo 与焦点

[确认] Enter 插入与 Backspace 删除必须支持 `Ctrl+Z / Ctrl+Y`，恢复同一个 `page_id`、位置和全部字段，包括正文、立绘引用、语音、音量、速度和自定义速度开关。

[施工约定] 文本输入仍保留可理解的编辑撤销；结构动作各对应一个 Graph Undo 单元。处理“提交当前草稿”和“插入下一句”时必须保证顺序：撤销插入先移除新句，已输入的原句不能顺带消失。不得同时让 TextBox 原生栈和 Graph 栈重复处理同一个快捷键。

焦点迁移属于相应编辑动作的 UI 结果，不另外增加一次业务 Undo。撤销删除时恢复被删 Page 并合理聚焦；重做时再次执行确定的相邻焦点迁移。

异步创建视觉控件后按稳定 Page ID 定位，不能按旧索引或“第一个 TextBox”误把焦点放入速度/音量输入框。

### 3.6 IME、折叠、只读与换行

- 中文 IME 确认候选、提交组合文本时，Enter 不新建 Page；结束组字后下一次普通 Enter 才新建。
- IME 的 Backspace 不触发删句。
- Shift+Enter 不绕过单句禁换行规则；Ctrl+Enter 不擅自增加其他新增动作。
- 粘贴显式 CR/LF 按既有禁换行规则拒绝或明确报错；不静默吞字符、不顺带实现自动拆页导入。
- 程序自动视觉换行可以保留，与存储 `\n` 区分。
- 聚焦已折叠相邻句时应先展开正文；折叠动画不能抢走输入。
- 节点内和 Inspector 都必须通过同一组验收；外部只读引用不能借快捷键修改。

### 3.7 UI 设计

保留现有台词卡片、句号标题、拖动把手、`+ / −` 与本句设置。不要为键盘优化重做整个台词面板。

正文区增加不抢眼的帮助文字或 Tooltip：

> Enter 新建下一句；空句按 Backspace 删除。至少保留一句。

帮助文字使用既有说明样式，不是永久弹窗。该提示只适用于正文，不要放在整张节点上让用户误以为任何字段都遵循该规则。

### 3.8 模块 A 验收

| ID | 测试 | 通过标准 |
| --- | --- | --- |
| A01 | 中间/末尾/空句 Enter | 都在当前句后插入；新焦点正确；不丢草稿、不拆原文 |
| A02 | 有文本时 Backspace | 只删字符；最后字符删完不在同一事件删 Page |
| A03 | 空句删除中间/首位 | 只删除当前句；上一句末尾/新首句开头正确 |

| A05 | 仅剩一项后再新增 | 唯一项快捷保护；新增后原唯一项可删 |
| A06 | 空格、动态块、长按键 | 不误判空、不穿透连续删多句 |

## 4. 模块 B：在线 / 离线玩家 DGR 状态检查 GUI

### 4.1 定位

[确认] 这是管理员针对某个玩家的**只读状态检查器**，用于玩家崩溃退出、任务卡住、Story 等待异常等排障。不是事件追踪器，不是自动修复器，不是全服后台。

只回答“服务器目前保存了什么、等待什么、哪些数据无法解释”。没有事件历史时，不得编造“昨天为什么崩溃”的结论。

### 4.2 入口和玩家查询

[施工约定] `/dgr debug` 无参数由有权限的游戏内管理员打开检查 GUI；保留现有带参数命令，不把现有测试命令映射成 GUI 修改按钮。

```text
玩家状态检查

┌ 玩家查询 ───────────────────────────┐
│ 玩家 ID  [ 输入玩家 ID          ] [查询] │
│ 输入服务器中该玩家使用的名称。            │
└───────────────────────────────────┘
```

硬要求：

- **输入框，不是玩家下拉框。**不枚举所有历史玩家供用户滚动。
- 对用户仅使用“玩家 ID / 玩家名”概念；不要求输入、不展示 UUID。
- Enter 可提交查询；空输入或明显不合法输入在当前卡片内提示，不默认为随机/第一个在线玩家。
- 查不到玩家、没有 DGR 记录、读取失败是不同结果，不可统一显示“没有任务”。
- 查询必须覆盖离线玩家；玩家无需上线、无需生成实体、无需登录后才可读旧记录。

内部继续使用既有稳定玩家身份索引。不得为了满足玩家名 UI 改成“以名字作为所有存档主键”。名称→身份转换由系统承担。

### 4.3 名称解析与旧服务器记录

[验证点] 先检查服务器现有 profile/name 缓存和本地持久记录能否可靠定位历史玩家。需要覆盖服务器重启后的离线查询，不能只靠本进程在线名单。

如果现有数据不足，只补**最小的持久名称映射**并与已有真实玩家身份关联；不建立通用账号系统，不调用外部网站要求管理员查询 UUID，不在请求期间自动按名字猜一个身份。

对于此前没有可靠名称记录的数据，必须报告“无法从本服现有记录定位该玩家”，不得错读另一个人。这个限制要在验证记录中写明，不能用“支持离线”掩盖未覆盖的旧数据情况。正常有映射的历史玩家应直接查到，不增加人工身份操作。

### 4.4 读取路径必须真正只读

[基线] Story/Session 由世界级 `CanonicalSessionSavedData` 保存，内部包含 Session Store、Story Store 和 continuation；Task 另有世界级 `CanonicalTaskSavedData`。这不是只有在线玩家实体才拥有的数据。[S6]

[验证点] 现有 `get(MapStorage)` 含 get-or-create，部分 bind/restore 路径会恢复、修正或移除不可用实例。因此不能把“调用一个带 snapshot 名字的方法”直接当成无副作用读取。

实现要求：

1. 已加载数据优先读服务器当前持有的 canonical 状态快照；未绑定的原始记录按必要范围读取副本。
2. 用读路径取得 `MapStorage` / 持久记录，不要求被查询玩家的 `EntityPlayerMP`。
3. 不运行 `start/resume/reset/recover/grantReward`，不创建 FakePlayer，不触发 Forge 游戏事件。
4. 不为查询重新推进 Flow、重新采样背包、重新发奖励或执行指令。
5. 节点或包缺失时，尽量保留并展示可读原始状态及关联错误；不得调用带删除副作用的可用性绑定路径清掉证据。
6. 单条坏记录不应使该玩家所有其他可读记录消失；无法安全解码的部分明确标为读取失败。
7. 保持服务器线程和现有同步约束；跨线程只处理已分离副本，禁止 UI/网络线程直接遍历可变 WorldSavedData。

在线与离线都查询 DGR 持久模型，但必须准确标注来源：例如“服务器当前状态”或“从最近可读存档加载”。离线不代表内存中状态必然等于最后一次磁盘写入。查询时间也不能冒充最后保存时间。

**不承诺从损坏且无法解析的文件恢复所有字段，也不承诺重建崩溃前未落盘状态。**只读诊断必须如实报告这些边界。

### 4.5 信息组织与卡片结构

GUI 分成三个可辨识功能区：

1. **查询区**：玩家 ID、查询/刷新、查询错误。
2. **结果导航区**：只列当前查询玩家的 Story，以及相关 Session/Task；长列表滚动或分页。
3. **详情区**：玩家摘要、所选资源状态、执行位置、等待/重复条件、关联异常，以卡片展示。

```text
玩家 ID [ GreyHat633                ] [查询]

┌ 查询结果 ─────────────────────────────────┐
│ GreyHat633 · 离线                           │
│ 数据来源：服务器已保存的 DGR 状态              │
└─────────────────────────────────────────┘

┌ 该玩家的内容 ──────┐  ┌ Story 状态 ───────────┐
│ 村庄主线           │  │ 村庄主线 · 已结束       │
│   初遇村长         │  │ 当前节点：……           │
│   清理矿洞         │  └──────────────────────┘
│ 其他故事……         │  ┌ 重复资格 ─────────────┐
│                    │  │ 冷却重复 · 尚未到期      │
│                    │  │ 上次完成：……           │
│                    │  │ 下次可用：……           │
└──────────────────┘  └──────────────────────┘
```

示意只规定区域与信息层级，不是要求仿制字符边框。Minecraft 端复用现有 DGR 工具窗风格、窗口几何与滚动能力；不要另起主题。窄窗口可以改成“结果页→详情页”，不能缩小到读不清。

不能默认只显示 ACTIVE 而把错误、已结束但仍在冷却、离线异常状态隐藏掉。可使用紧凑状态过滤，但默认须让管理员看到有诊断价值的异常记录。

### 4.6 应展示的数据

| 类型 | 信息 | 规则 |
| --- | --- | --- |
| 玩家 | 玩家名、在线/离线、查询时间、数据来源 | 不显示 UUID；未知时间不伪造 |
| Story | 名称/资源 ID、真实状态、当前节点/入口、Wait、等待对象、已保存 Logic | 用中文标签，必要时在详情附技术标识；不把 Wait 当成新的持久生命周期枚举 |
| Session | 相关 Story/placement、当前节点、作者页位置、状态、已保存 continuation 关联 | 不把 display segment 当作者 Page；离线不推断玩家当时屏幕内容 |
| Task | 任务及所属 placement、Objective 状态/进度、已存逻辑、结算/奖励相关已存状态 | 不能按 Task Resource ID 合并不同 placement 的实例 |
| 重复条件 | 是否可重复、模式、正常完成时刻、下一次资格/剩余时间、阻止原因 | 必须调用与真正启动检查同一语义的只读判断 |
| 异常 | 缺失包/资源/节点、不可解析字段、关联不一致 | 区分确定的结构错误与“仅凭快照无法判定” |

Task 详情按现有逻辑模型解释目标，不自动生成一条假的顺序流程。不跨任意 AND/OR 猜测奖励归属。

### 4.7 安全与规模

- 所有请求在服务端校验管理员/现有编辑权限；客户端隐藏按钮不算鉴权。
- 请求和响应有边界、分页/长度限制及请求关联；过期响应不能覆盖最新玩家查询结果。
- 只传目标玩家所需信息，不默认传全服所有玩家数据。
- 查询按钮加载时有反馈，结束/失败后可继续使用；大量历史记录不能堵死 GUI。
- 不建立常驻追踪缓冲、不定时遍历全服、不加 Event Trace。
- 读取不能改变玩家状态字节、奖励记录或正常运行游标。
- 服务器已整体卡死时游戏内 GUI 也无法执行请求；恢复服务后可查保留下来的数据。本版不额外开发服务器停机文件浏览器。

### 4.8 模块 B 验收

| ID | 测试 | 通过标准 |
| --- | --- | --- |
| B01 | 玩家名输入查询 | 无 UUID 输入/显示，无历史玩家下拉框 |
| B02 | 在线→下线→重启后离线查询 | 同一玩家记录可定位；不用登录、不创建玩家实体 |
| B03 | 长期历史玩家 | 不只查本进程见过的玩家；不能失败后猜身份 |
| B04 | 不存在/无 DGR 记录/损坏记录 | 三种状态有准确且不同的反馈 |
| B05 | 只读性 | 查询前后 canonical/奖励数据无非运行性变化；不恢复执行、不发奖励 |
| B06 | 同资源不同 placement | 结果不合并、不串玩家、不串 Story |
| B07 | 缺失资源/旧节点/未绑定原始记录 | 能读部分照常展示；不能为了 bind 清除异常证据 |

## 5. 模块 C：动态内容——可视化引导，不让作者背语法

### 5.1 作者使用方式

[确认] 对外名称为 **动态内容**。每个支持的文本编辑区有明确的 `＋ 动态内容` 按钮，不能只在帮助文档里藏几个 token，也不能要求作者在全局先声明变量。

正文中显示可辨认的原子内容块，例如：

```text
┌ 第 2 句 ──────────────────────────────────┐
│ 台词文本                    [＋ 动态内容]  │
│ 欢迎回来，〔玩家名称〕。                     │
│ 你现在有〔持有数量：铁锭〕个铁锭。           │
│                                            │
│ 文本容量：按实际字体度量；含动态估算          │
│ Enter 新建下一句；空句按 Backspace 删除。     │
│ ▶ 本句设置                                 │
└──────────────────────────────────────────┘
```

示意中的 `〔……〕` 表示视觉块，不是要求作者手输的占位符，也不是最终语法。

### 5.2 插入选择器必须有完整引导

点击按钮在当前编辑器附近显示有边界的小型选择面板，结构为：

- 标题：`插入动态内容`。
- 一句帮助：`在游戏中自动替换为当前玩家的实际信息。`
- 可用内容列表：名称、简短说明、示例。
- 需要选择物品时，显示独立的“对象设置”区及 `插入` 按钮。
- 不需参数的项目可以直接插入；有参数的项目未选定时禁止提交并说明原因。

```text
┌ 插入动态内容 ─────────────────────────┐
│ 在游戏中自动替换为当前玩家的实际信息。   │
│                                        │
│ 玩家名称                               │
│   当前玩家的游戏名称。例如 GreyHat633。 │
│ 玩家经验等级                           │
│   当前 Minecraft 经验等级，例如 12。    │
│ 指定物品持有数量                       │
│   按选定 DGR 物品匹配规则统计。          │
│                                        │
│ ┌ 对象设置 ────────────────────────┐   │
│ │ 物品 [ 选择物品……            v ] │   │
│ │ 支持从资源库拖入允许的物品资源。  │   │
│ └─────────────────────────────────┘   │
│                           [取消] [插入]│
└──────────────────────────────────────┘
```

选择器展开不是新增 Preview 模式。这里的示例是解释机制的静态示例，不是假装读取了后台 Minecraft 的实时值。

### 5.3 首批提供的动态内容

| 内容 | 显示给作者的解释 | Runtime 数据来源 |
| --- | --- | --- |
| 玩家名称 | 当前玩家的游戏名称 | 正在接收该内容的玩家；不使用 OP 名称、Studio 用户名 |
| 玩家经验等级 | Minecraft 当前经验等级，不是总经验点数 | 权威玩家数据 |
| 指定物品持有数量 | 当前持有且匹配所选 DGR 物品/允许物品组的数量 | 复用现有 DGR 物品匹配与背包范围语义 |

[验证点] 物品组只在现有匹配能给出明确数量时开放；同一个 ItemStack 匹配组内多个成员只统计一次。哪些背包槽位计入必须与既有物品目标统计一致，并写入提示和测试，不另造一套“所有模组容器都扫描”的规则。

不添加玩家可写变量、Task/Story 运行实例占位符、任意代码/公式、任意 Mod 字段访问。后续有明确需求再扩展，不在这版凑数量。

### 5.4 支持字段的明确清单

| 位置 | 本版支持 |
| --- | --- |
| Session【台词】 | 每个 Page 的正文 |
| Session【选择】 | 提示和选项文本 |
| Task | 任务说明、Objective 说明 |
| Story【标题】 | 主标题、副标题 |
| Story【消息发送】 | 面向玩家的消息正文 |

不支持资源 ID、节点 ID、端口、内部名称、文件路径、资源显示名、ActorID/ItemID 技术字段、`execute_command` 等指令字段。

两处已有的字段都必须接入：Inline 和 Inspector。Task 说明等本来属于资源属性的字段继续在原入口编辑，不为了“全覆盖”制造一个新的节点内字段。

### 5.5 原子编辑、焦点与 Undo

- 动态块有明确外观；Hover 提供来源/含义，点击可重新选择参数。
- 方向键可越过整块；删除只删除整块；文本范围选择触及块时按完整原子处理，不产生半个 token。
- `Ctrl+Z / Ctrl+Y` 恢复插入、删除、对象更换及正文，不创建另一个不可协调的 RichTextBox 撤销栈。
- 打开选择器前记住原正文选区/光标；插入时替换该选区并回到正确位置，不能一律追加末尾。
- 选择器确认用的 Enter 不触发 A 模块的新建 Page；取消不能改原文。
- 资源拖入物品选择框只改变该对象参数，不穿透修改画布其他节点。
- 只读引用的正文和动态块不可借弹窗变更。

### 5.6 Copy/Paste、搜索与持久化

[施工约定] canonical 文本字段继续以字符串保存，使用受控、可转义的 machine token；正常 UI 只展示可视化块。具体 token 文法在首个实现阶段记录一次，并在 Studio / Runtime 共享同一套测试向量，不能双方各自猜字符串。

必须满足：

1. 保存、重开、复制节点、复制文字不会把动态块变成普通标签字面值。
2. DGR 内部剪贴板支持完整动态数据；普通文本副本使用可回读的编码，不伪装成真实玩家值。
3. 普通作者原文与机器标记可区分，保留转义途径；不把用户正常括号文本自动变成未知 token。
4. 未知/损坏 token 明确报错；普通旧文本不受影响。旧数据与新 token 的冲突处理必须在迁移测试中覆盖，不能静默更改原文。
5. 解析器只认识白名单内容；不递归解析替换结果，不执行反射/表达式，不进行无限展开。
6. Item 引用必须纳入既有校验、依赖收集、导出和重命名/引用更新路径；不能藏在字符串里使导出漏依赖。
7. 搜索结果应可按正文及可见动态内容名称定位，不能回显一整串技术 token 淹没内容。

不要仅用几个 `string.Replace` 做完这项，也不要为了动态块把整个项目改成富文本文档体系。

### 5.7 Runtime 求值时机与信息一致性

- 动态值由真实 Runtime 对目标玩家求值；不在导出时写死、不使用客户端自报背包数据。
- 台词进入作者 Page 时取得本次展示使用的完整解析文本，再交给既有排版/显示分段/打字机。
- 同一次展示的分段、重发、历史记录使用同一份解析结果；不能在 1A→1B 时因为背包变化重新切段或重启语音。
- History 保存当时真正显示的完整作者页文本，不保存将来会重新变化的模板结果。
- Choice 以当前展示快照解析；选择仍由现有服务端合法性校验，动态文字不是权限或物品交易授权。
- Task 说明/目标文本沿用现有 UI 投影刷新节奏求值，避免每帧全背包扫描或全图广播；库存变化造成文字更新也不能触发普通进度 Toast。
- Title/消息在该次执行时求值。
- 重连恢复同一作者页、重复报文等边界需复用既有页面身份/epoch；如需存储本次解析结果，只增加必要数据，不建立事件历史系统。

### 5.8 无法求值与容量

缺失物品引用在 Studio 显示明确的错误块，例如 `〔物品引用缺失〕`，进入现有问题列表；不能悄悄当成 0。已找到合法物品身份、实际持有为零时显示 0。身份未绑定/匹配不可用应与确实为零区分。

Runtime 不可用数据采用可辨识的 `未知`/`数据不可用`，并进入现有有节制的诊断渠道；不得因为展示文本求值失败执行其他玩家状态、回退成 OP 背包或崩掉整个会话。

文本容量沿用既有实际字体度量及 SAFE_CAPACITY，不能按动态块标签字数计算。能确定支持上界的用保守估算；不能确定上界的明确写“动态内容为估算”，不得宣称精确。**示例中的 144 不是固定容量数值。**

超建议容量仍允许保存/导出并提示；Runtime 先解析真实文本再测量，沿用现有本地 display segment 机制。作者 `page_id`、页数、最终 CONTINUE、单页语音与自动播放规则不得因此改变。[S7]

### 6.4 各模式需要的字段

| 模式 | 展示字段 | 不展示的内容 |
| --- | --- | --- |
| 无条件 | 重复方式；一句简短解释 | 冷却时间、日期、星期 |

| 定时 / 每周 | 时间规则 + 星期 + `HH:mm` | 月日 |
| 定时 / 每年 | 时间规则 + 月/日 + `HH:mm` | 年份、星期 |

冷却单位**只允许秒、分钟、小时**，不增加“天”，不自动把 24 小时转换成“1 天”。

年规则使用月日控件，不强迫用户先选一个假年份。时间输入必须有明确格式和可见校验，不用自由英文字符串要求用户学习。

### 6.5 规则语义：先算资格，再走现有驱动

所有模式遵循：

> 当前没有正在进行的该 Story，且具备对应的重复资格，且满足现有【开始】节点的实际驱动条件，才允许新一轮开始。

**到期不是自动启动。**不定时替玩家点击 NPC、不自动生成区域进入事件、不因为 12:00 到了就无条件执行 Story。

| 已保存状态 | 再次开始的准入 |
| --- | --- |
| 从未运行 | 按原始开始驱动；重复条件不把首次运行变成预约开放功能 |
| ACTIVE | 不新开并行实例；继续遵守现有活动实例行为 |
| 正常 TERMINATED，未勾选 | 不可重复 |
| 正常 TERMINATED，无条件 | 满足现有驱动即可重复 |
| 正常 TERMINATED，冷却/定时未到期 | 拒绝新一轮，状态不被修改 |
| 正常 TERMINATED，冷却/定时已到期 | 恢复资格；等到有效驱动时才开始 |
| ERROR | 不由本版自动重复；保留异常供 Debug 检查 |

ERROR 不自动重试是本版明确的目标行为，施工时须核对原有 `repeatable` 对所有 terminal 状态的处理，不能假定旧代码已经区分正常结束和 ERROR。

### 6.6 冷却重复

```text
next_eligible_at = last_normal_completion_at + cooldown_duration
eligible = server_now >= next_eligible_at
```

- 基准是**整个 Story 正常完成时刻**，不是 Story 启动、某个 Task 完成、Session 结束或服务器启动。
- 单位转换用足够范围的整数时间值并检查溢出；冷却值必须大于 0，0 应使用无条件，不用静默修成 1。
- [施工约定] 第一版冷却数值为正整数；不通过浮点误差处理跨天长时段。
- 离线、服务器停止期间现实时间继续经过；重启不重新开始倒计时。
- 普通查询、失败的触发尝试、未变化包的 reload 不重置完成时间。

例：故事 10:00 开始、13:30 正常结束、冷却 24 小时，则次日 13:30 才恢复资格。

[基线] `CanonicalStoryInstance` 已有 `activationTime` 与 `terminalTime`，且 ERROR 也可能取得 terminalTime。优先复用可靠字段，但必须同时检查正常 TERMINATED，不能把任何 terminalTime 都解释为成功完成。[S8]

### 6.7 定时重复

```text
next_eligible_at = 本次正常完成时刻之后，第一个严格更晚的有效计划时刻
eligible = server_now >= next_eligible_at
```

- 每日：如每日 12:00。
- 每周：如每周一 12:00。
- 每年：如每年 12 月 25 日 00:00。

例：每日 12:00，11:30 完成→当天 12:00；13:00 完成→次日 12:00；恰好 12:00:00 完成→下一天，不能立即获得同一时间点的额外一轮。

**获得资格后保持可用，直到真正新一轮开始。**错过当天 12:00 不需要等到下一次恰好 12:00；玩家 15:00 回来仍可以触发。不要每次查询都以“当前时间”寻找下一次而把资格永远推到明天。

跨越多个计划点不囤积多次次数。新一轮在后续正常完成后重新计算一个下一次计划点。Story 正在运行时跨过计划点，不中断、不重置、不偷偷创建新实例。

### 6.8 现实时间、时区与日历边界

以下为使实现可测试的**施工约定**，不增加作者侧多层菜单：

- 使用服务器现实时间，不使用 Minecraft 世界昼夜、睡觉结果、`/time set` 或客户端本地时钟。
- 定时计算使用明确固定的服务器时区；首次默认可取主机时区并在现有配置体系内保存。Debug 显示实际使用时区，Studio 只提示“以服务器现实时间为准”，不伪造下一次真实资格时间。
- 不为每个 Story 增加时区下拉；不要由 Windows Studio 时区决定 Linux/其他服务器计划。
- 不存在的日期要校验；2 月 29 日的年度规则跳过非闰年，不擅自改成 2 月 28 日。
- 若时区有夏令时：跳时缺失的计划时刻按该日其后第一个有效时刻处理；回拨重叠的本地时刻仅取第一次对应时刻，不发两次资格。
- 时钟服务要可注入，边界测试使用受控时间；禁止为测试真的等待 24 小时。
- 系统时钟倒退不得损坏时间值或生成重复轮次。若发生异常时间，应可诊断，不能静默重置 Story 或清空冷却。

上述是时间规则自身的必要边界，不是开发一个通用定时调度平台。

### 6.9 数据、持久化与迁移

[施工约定] 保留现有 `repeat_policy = once / repeatable` 作为总开关，增加受控的 `repeat_condition` 描述细项；具体序列化必须在 Studio、DGRS 校验与 Java Runtime 中一致。

示意契约如下；施工时可采用等价字段，但要一次记录并配对测试，不能留下多套同义旧字段：

```json
{
  "repeat_policy": "repeatable",
  "repeat_condition": {
    "type": "cooldown",
    "value": 24,
    "unit": "hours"
  }
}
```

```json
{
  "repeat_policy": "repeatable",
  "repeat_condition": {
    "type": "scheduled",
    "period": "weekly",
    "weekday": 1,
    "time": "12:00"
  }
}
```

要求：

- 无条件对应 `none`；旧 `repeatable` 无新增字段时自然按无条件解释；旧 `once` 仍仅一次。
- 作者规则与玩家完成时间/下一次资格数据分开；不把玩家状态写入 DGRS。
- 规则切换是一次有效编辑事务。Undo 恢复原完整规则，不留下同时生效的冷却/定时字段。
- 取消勾选不触发业务删除；可保留最近有效配置以便再次勾选使用，但 `once` 必须忽略它的运行效果。
- 无效数值和半输入时间保留为可见草稿，不提交虚假的默认值；沿用现有有效数据/草稿错误边界，不擅自改全局保存策略。
- 不把每次读取 next eligibility 做成写操作。对缺失完成时间或不可信旧记录明确报错，不以查询时的 now 假造完成时刻。
- 进度仍按玩家隔离；同 Story 不同开始驱动不能绕过同一重复资格。
- 保持既有包代际规则。相同包的正常 reload 不重置计时；内容实际更新导致的旧实例处理按现有机制验证，不重新设计无损热迁移。

### 6.10 Runtime 接入

重复资格是现有 Story 准入判断的增强，不是新节点，不是新任务目标，不是常驻计时线程。

检查并接入所有正常启动入口，包括角色、区域、逻辑、Flow 驱动及生产命令入口；候选列表显示与最终服务端接受启动必须一致。最终启动时重新校验，避免列表过期或重复请求创建两轮。

必须保留既有启动的边沿/观察语义。定时到期本身不生成新的 Logic 上升沿；同一高电平或区域停留能否再次触发，继续由既有开始驱动模型决定。

只有**实际接受的新一轮**才执行既有子实例清理和新轮次初始化。一个被冷却拒绝的尝试不能先重置旧 Task、奖励记录或 Story。

Debug 使用同一个资格判断并展示“进行中 / 仅一次 / 冷却中 / 等待计划时刻 / 已具备资格 / 异常”，不自行实现第二套时间算法。

## 7. 跨模块集成与实现边界

### 7.1 A + C：必须作为同一正文编辑体验验收

台词快捷输入和动态块不能由两个人分别实现两个互不兼容的文本控件。需要共用“当前正文、空内容判断、选区、IME、提交、Undo/Redo、焦点恢复”的明确接口。

动态选择器的 Enter、编辑器本身的 Enter、IME 的 Enter 必须有正确优先级：

```text
IME/子交互正在消费 → 只处理对应输入
否则正文普通 Enter → 新建下一句
其他字段 Enter → 保留该字段自己的提交语义
```

Backspace 先按正文原子删除；**按键开始时正文已空**且 `pages.Count > 1` 才删句。不让处理后的空状态在同一次输入里继续触发结构删除。

### 7.2 B + D：同一事实来源

重复规则由 Runtime 计算；Debug 只读取并解释结果。不能出现 UI 写“可重复”、实际启动失败，或者 Debug 为了计算倒计时修改完成时刻。

### 7.3 C + 现有媒体/排版

动态解析不改变 Voice 的每作者页归属，不创建额外 DGRS 页面，不用滚轮正文阅读代替分段，不重写已有媒体缓存。

### 7.4 原有功能回归

本版不得破坏：

- 资源库的 Owned/Referenced/外部只读规则、拖放选择。
- Group 嵌套、合并、取消组合、删除、复制、撤销；折叠动画下的连线稳定性。
- 多 Page、作者页 ID、长文本分段、自动播放、记录、Choice 行为。
- Task 逻辑、结构 Toast、Tracker、Reward 事务与已绑定物品显示。
- Nominator、唱片机、音量和媒体基本行为。
- 手动 `.dgrs` 导出与 `/dgr reload`。

这些是回归项，不是授权重新开发上一版模块。

## 9. 验收与交付

### 9.1 验收由四部分组成

| 验收 | 要证明什么 |
| --- | --- |
| 自动化正确性 | 数据契约、编辑历史、时间边界、只读性、玩家隔离 |
| 实际 UI 验收 | 分区、美观、信息层级、输入焦点、主题、窄宽度、IME、真实鼠标键盘操作 |
| 规模/压力回归 | 新功能不使现有大型工程出现明显性能或稳定性退化 |
| 真实同包 E2E | Studio 正式产出的同一 `.dgrs` 在 Minecraft 中真正运行 |

不能用编译成功、单元测试成功或开发者截图代替用户使用链路。

### 9.2 UI 截图与操作证据清单

以下场景至少在节点内和 Inspector 适用位置分别验证：

- 重复关闭、无条件、冷却、每日、每周、每年；正常值和错误值。
- 重复卡片收起、展开、快速反向点击，带连线的实际画布。
- 台词一项、多项、动态块混排、较长正文、插入新句、删除首句与最后剩余句保护。
- 动态选择器默认说明、物品对象选择、缺失引用、取消与插入后的焦点。
- Debug 查询前、加载中、在线、离线、无记录、异常记录、长列表、窄窗口。
- 浅/深主题、Windows 缩放；Minecraft 支持的 GUI 尺寸及文本大小。

截图必须来自当前构建的真实界面，注明版本/构建、界面入口、主题、缩放和验证项。静态截图无法证明焦点、IME、折叠、拖放与 Undo；这些需操作记录或录屏补足。

### 9.3 规模回归不是独立功能

复用/补充固定测试数据，包含现有的 300 节点 / 300 Group 场景，以及多 Session/Task、多台词页、动态块和大量离线玩家记录。

- 在同一环境对比 `0.3.3.3` 与候选版：项目打开、切换图、拖动、搜索、保存、导出。
- 新功能测自身成本：长文本原子编辑、动态菜单、重复卡片动画、单玩家大量状态查询。
- 记录样本数、median、P95、max、内存，以及计时包含/不包含的内容。
- 现有 WPF layout 计时不等于真实输入到屏幕帧延迟；不要混称为 FPS。
- 预先按基线波动与实际可用性确定本轮回归判据，不能测完再挑有利指标。
- 出现可重复的明显退化，定位具体瓶颈再修；禁止先假定必须懒加载、虚拟化或重写全图。
- 同时检查数据正确性：不能以丢页、丢连线、漏状态、跳过校验来获得“更快”。

性能正常就不额外优化。此流程不进入“0.3.3.4 新增功能”清单。

### 9.4 强制真实 E2E

本版 E2E 内容至少包含：

1. 通过 Enter 创建、Backspace 删除并 Undo/Redo 的多句台词；实机页序和文本正确。
2. 含三种动态内容的文字；两个玩家不同名字/等级/背包，真实显示不同。

7. 一个异常/缺失关联的诊断样本，能够只读显示错误且不自动清理原始状态。
8. 未变化包手动 reload、旧 once/repeatable 内容、新版内容的基本回归。

时间边界可在隔离的自动化环境使用可注入时钟；不得为了验收随意改生产服务器时钟或玩家正式存档。

## 附录 C：Codex 易错实现红线

> 这一页应在最终代码审查时逐项检查，不能只在开工时读过一次。

1. **不得保护固定第一页。**任何 Page 都能在 `Count > 1` 且满足空句条件时被快捷删除，包含最早创建的和当前索引 0 的 Page。
2. **不得用尾部追加冒充 Enter 后插。**中间句 Enter 必须插到紧邻后方。
3. **不得让一个 Backspace 同时删完文字、删句、再删上一句。**按键处理前判断，结构动作防长按穿透。
4. **不得让 IME 确认或动态选择器确认顺带新增台词。**
5. **不得以新 TextBox/RichTextBox 的默认行为破坏已有 Undo。**新增与删除恢复原 Page ID 和全部数据。
6. **不得把关键参数只放 Inspector。**重复配置和适用的动态内容编辑要在节点内完整可用。
7. **不得把 UI 做成无分区长表单。**复用现有卡片与说明样式，使用折叠而不是裁切或删掉功能。
8. **不得给玩家查询做下拉框或要求 UUID。**内部身份解析不转嫁给管理员。
9. **不得把离线查询实现成“先要求玩家在线”。**重启后的历史记录也是验收对象。
10. **不得让查询触发恢复执行、奖励重试或丢失资源清理。**状态检查必须只读。
11. **不得把 snapshot 当事件历史。**未知原因要明说，不增加 Event Trace 或自动修复。
12. **不得把动态内容做成隐藏语法或万能变量。**按钮、说明、示例、原子块是必交内容。
13. **不得把未知物品身份当成持有数量 0。**合法零值与无法求值要区别。
14. **不得把台词显示分段写成新 Page。**替换后的真实文本继续沿用既有显示安全边界。
15. **不得从 Story 开始或 Task 完成计算冷却。**只从整个 Story 正常完成计时。
16. **不得到点自动启动 Story。**重复资格和开始驱动是两个同时必须满足的条件。
17. **不得每次查询都算“从现在起下一个计划点”。**否则已到期资格会永远被推后。
18. **不得把 ERROR 当正常完成自动重试。**也不得为了显示冷却而覆盖错误证据。
19. **不得添加天单位、Cron、每月或绝对日期等额外规则。**本 PLAN 的模式边界已经明确。
20. **不得重新包装已有热更新。**用户手动 reload；无自动联动按钮，无 Preview。
21. **不得用脚本生成的另一个包替代 Studio 正式导出包验收。**
22. **不得把所有测试标为通过而不保留证据。**未执行写未验证；UI 差或交付文件过期就是未完成。
