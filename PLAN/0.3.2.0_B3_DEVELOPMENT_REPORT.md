## B. Fingerprint v1 Contract

Logical install identity remains:

```text
(package_id, story_id)
```

`story_id` is not derived from mutable content. A generation key is:

```text
(package_id, story_id, content_fingerprint)
```

`content_fingerprint` is 64-character lowercase SHA-256. The digest input is:

1. fixed ASCII header `DGR-PACKAGE-CONTENT-FINGERPRINT-V1\0`;
2. length-prefixed UTF-8 `format`, `format_version`, `schema_version`, and `story_schema_version`;
3. authoritative records for `project`, `story`, `actor`, `item`, `item_group`, `dialogue`, `quest`, `canonical_story`, `canonical_membership`, `session`, `task`, and optional `story_logic_graph`;
4. records sorted by `role ASC`, then `path ASC`;
5. each record framed as `uint32_be role_length + role_utf8 + uint32_be path_length + path_utf8 + uint64_be content_length + raw_content_bytes`.

The digest excludes ZIP timestamps, physical entry order, file timestamps,
`producer_version`, `package_version`, `package_id`, and `story_id`. Both DGRS
archives and compatible unpacked packages use detached, already-validated raw
resource bytes.

Automated outputs:

```text
FINGERPRINT_SAME_CONTENT_STABLE=PASS
FINGERPRINT_RESOURCE_CHANGE_DETECTED=PASS
FINGERPRINT_ROLE_CHANGE_DETECTED=PASS
FINGERPRINT_ENTRY_ORDER_INDEPENDENT=PASS
FINGERPRINT_REPEAT_POLICY_CHANGE_DETECTED=PASS
```

## E. Runtime Retirement Boundary

For `UPDATED`, `REPLACED`, and `REMOVED`, retirement filters the world-level
persistence stores by Story ownership across all player UUIDs and removes:

- canonical Story instances, including terminal ONCE cursors;
- canonical Session instances;
- canonical Task instances and objective progress;
- pending Story/Session continuations;
- Task subscription-index entries associated with retired instances.

`UNCHANGED`, `ADDED`, and rejected candidates do not retire existing runtime.
Targeted probes demonstrate that another Story's Story/Session/Task state is
retained.

The lifecycle does not touch Nominator entity bindings, NPC identity data,
item identity bindings, inventories, entities, or author-defined identity
mappings. Existing `tarven_boss`/`copper_coin` world bindings therefore remain
available (or dormant if their resource is absent) rather than being deleted.
No graph migration framework was introduced.
