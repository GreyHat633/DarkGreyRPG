# 0.3.3.4 联机媒体传输窗口修复（2026-09-30）

状态：本轮窗口实现、构建、定向探针及所列隔离实机验证完成。USER_ACCEPTED=NO；RELEASE_READY=NO。此前媒体报告中的“冷缓存单张约 24 秒停等瓶颈”由本轮修复与新结果更新；其他未覆盖项不关闭。

## 修复

- 每文件从一次只请求一个 32 KB 分块，改成最多 8 个分块在途。先用首块确认总大小，再填满窗口。收到的数据、正在写入的数据共同计入窗口，最多保留 256 KiB payload / 活动文件；3 个包同时准备时协议窗口合计最多 768 KiB，不含网络及短期拷贝开销。
- 主线程只管理有界窗口；乱序响应暂存，连续分块批量交给现有单线程 IO 写入。缺块超过 2 秒只重请求缺失项；已收到或正在写入的不重发。下载最终仍通过整文件 SHA-256 校验。
- 失败/退役清空窗口；重试创建新请求 ID，旧响应不能混入新一轮。断线后的旧异步完成结果继续检查当前 State 身份及 retired 状态。
- 读取实例以“所有分块已读取”判断完成，修复乱序下最后一块提前到达导致过早关闭、重新校验的问题。保留 generation lease、64 实例上限和空闲回收。
- 服务端单连接请求上限从 32 调整为 256 次/秒（有效负载请求量理论上限 8 MiB/秒），以容纳三个 8 块窗口；全局工作队列/在途上限、每块大小、64 MiB 单媒体上限和逐请求授权检查未放宽。固定时间窗边界仍可能有短时双倍突发，工作队列另有独立上限。
- 不改报文格式、不改通用网络调度、不改 Story 真正 Start、3 包并发、10 包缓存、整包 Ready/LRU、运行保护及按需解码语义。Gramophone 和 Studio 未修改。

相关文件：CanonicalMediaClient、CanonicalMediaServer、MediaTransferReaders、新增 MediaTransferWindow；新增窗口探针并扩展读取探针。
