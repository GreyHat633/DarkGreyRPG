# 3. 不得回退的现有规则

## 3.1 运行与身份

Task 内仍为纯 Logic；奖励属于 Task，自带多项正负资源结算。Story / Session 保留自己的 Flow。玩家状态仍由服务端管理，客户端不得凭 HUD、历史或设置自行完成任务。

Story ACTIVE 时任何 Start 均不得重入；流程驱动只命中对应入口；逻辑条件重复启动遵守 False→True 与 repeatable 规则。Story 终止输出及公共逻辑端口身份稳定，改名/排序不得断线。

保留 NPCID、ItemID、GroupID 及精确/模糊匹配语义。本版留声机自己的设备定位是运行细节，**不是让作者管理全世界方块的 BlockID 系统**。

物品提交仍是：指定物品 + 指定提交角色 + 数量；真实实体交互、足量检查、原子扣除与完成。禁止恢复任务菜单远程提交。

## 3.2 UI 与多句台词

保留 `pages`、稳定 `page_id`、每句配置、`line_page_index` 和播放序号防重。默认跟随玩家速度；启用“自定义显示速度”才覆盖。点击先补全当前句，再次点击才继续。

设置或历史窗口位于会话之上时，底层会话只绘制、不接受点击。关闭上层窗口恢复当前句，不推进、不重新播放、不重置打字进度。ESC 仍是正常退出菜单/关闭当前上层界面的既定行为，不能变成放弃会话。

保留“表情差分”“头像”“语音/音效”“播放完再继续流程”等最终术语；保留任务、会话、故事在 Studio 中的特殊表头配色。游戏三套主题不改 Studio 自己的主题体系。

## 3.3 任务通知与媒体

保留 Toast 结构变化事件、三卡上限、合并、排队、动画和初始同步去噪。仅接取、目标完成/激活、任务终态等进入 Toast。需要时可在这种卡内显示计数，但**计数变化本身不是发卡理由**。[S03]

故事媒体仍在真正 Start 时预加载；Flow/Logic 关联沿输出方向遍历，不因预加载启动 Story。最多 3 包并发，10 包名额，运行包保护、非运行包 LRU。不能为了留声机把限额放大或塞入“伪故事包”。[S04]

保留 DGRS 自包含。保留正式归档媒体的流式校验、不可变代际、磁盘物化缓存与异步分块；不要将全部媒体重新放入 JVM 常驻 `byte[]`。不能仅凭基线仍有某个 `Map<String, byte[]>` 就认定归档主路径没有修复，必须按实际构造与调用路径判断。[S12]

## 3.4 目录与兼容

所有新增文件仍归入 `DarkGreyRPG/` 统一根目录；用户 `StoryPackages/` 只放原始 `.dgrs`。继续使用 `Cache/StoryPackagesRuntime/<安装路径哈希>/`；不恢复 `.dgrs-runtime`。

本版不开展“清理所有旧兼容”的额外工程。0.3.3.1 最后已认可的读取归一化可保留；新增字段使用明确默认，不制造双 Runtime。凡不需要变更的资源身份、已保存选择、任务和奖励收据均保持。

# 6. WP-A：玩家设置、主题与共享 UI

## 6.1 设置菜单内容

现有 P 窗口保留非暂停、拖动、四角缩放和本地保存能力。改成清楚的分组/分页，不另开一套管理控制台。

| 分组 | 控件 | 默认 / 语义 |
|---|---|---|
| 外观 | 主题 | 灰黑（默认） / 浅白 / 蔚蓝。 |
| 外观 | 对话框背景不透明度 | 0–100%；100 表示完全不透明；默认与当前观感接近。 |
| 外观 | 文字大小 | DGR 自己的可读字号/比例预设，不替用户修改原版 GUI Scale。 |
| 阅读 | 台词显示速度 | 保留 0–120 字/秒，默认 30，0 立即显示。 |
| 声音 | 语音/音效 | DGR 当前台词通道的独立音量，默认 100%。 |
| 声音 | 会话音乐 | DGR Session 音乐独立音量，默认 100%。 |
| 声音 | 环境留声机 | 所有留声机的玩家个人音量乘数，默认 100%。 |
| 操作 | 恢复默认 | 只恢复这些偏好；窗口位置是否恢复必须另有明确动作，不混进此按钮。 |

**不添加任务提示参数。**不添加缓存数量、并发、垃圾回收间隔等玩家滑块。保留已有快捷键设置入口；历史动作默认未绑定，用户在原版控制界面自行绑定。

文字大小实施默认可以先采用 100% / 125% / 150% 三档，并在实机验证后确定。它是可读性取值，不是用户已经指定的百分比；不能无限放大后以截断所有目标/选项解决问题。

## 6.2 主题覆盖与视觉要求

建立“当前主题快照→语义颜色”的最小映射。语义包括：主底板、内容底板、正文、次级文字、分割线、按钮、悬浮、选中、禁用、错误、遮罩。渲染器不各自维护另一份主题分支。

三套风格：

- **灰黑**：保留当前默认氛围，灰黑底、清楚浅字，不突变为金色旧 UI。
- **浅白**：浅白/浅灰底、深色正文；不能把现有白字原样放在白底上。
- **蔚蓝**：明亮、清爽的蔚蓝强调色，配合中性可读背景；不得做成深蓝、藏蓝或海军蓝主题。

必须覆盖当前可到达的对话、选项、I 任务窗口、追踪 HUD、Toast、P 设置、记录窗口、Story/提交选择窗口、留声机配置，以及现有 DGR 指名器/工具窗口所共用的外观。只允许窄范围换肤接线，不能顺手改其已冻结业务。

错误/警告除了颜色还有文字/图形含义，不能全改成主题强调色而失去辨识。标题、CG、头像等作者内容不是 UI 底板，不能随主题被染色。

## 6.3 不透明度与字体

背景不透明度只作用于对话底板。不能把正文、头像、选择高亮一起乘成透明；0% 背景时仍能看清文字，边框/文字必要的描边应按主题处理。

不透明度不决定命中：看得透明不等于允许点击穿透到世界。设置/记录盖在会话上时，底层不得抢输入。

文字布局采用同一测量结果计算换行、高度、滚动区域和命中矩形；不要只对绘制调用缩放，而让按钮位置留在旧尺寸。要覆盖中文、英文长词、格式码、换行、Unicode 与大 GUI Scale。

设置页使用真实渲染组件或同一布局算法做样例预览，内容包含姓名、头像占位、长中文、长选项；预览不得创建真正 Session、写历史、触发网络、奖励或播放默认音乐。

切换外观实时生效；保存安排在结束手势/关闭窗口，不在 MouseMove 每帧写盘。台词速度继续按现有“进入本句时确定”规则；设置预览可即时变化，不能重建真实句子来演示速度。

## 6.4 音量合成

采用现有音频引擎与分类，不新建第二套全局声音系统。概念公式：

```text
实际 DGR 源音量
= 内容设定音量 × 玩家该类 DGR 音量 × 进入/离开/淡入淡出系数
  × 原版对应音量分类（由现有链路恰好应用一次）
```

原版 master 由引擎已有机制处理，避免重复相乘。语音/音效沿用当前分类接线，会话音乐/留声机走音乐分类，且仍可分别调 DGR 乘数。

将某类设为 0 不改变 Story 或 Objective，不自动取消台词，不停止别的 Mod 音源。修改音量时更新当前声音，不从头重建播放器。

**留声机之间不得因为共享一首音乐或音量设置而只保留一个播放实例。**文件可去重，播放实例不能合并。

## 6.5 按键和 GUI 层级

- 设置的打开与关闭读取同一个实际 KeyBinding；P 仅默认键，不硬编码为唯一关闭键。
- 历史、任务菜单等新操作遵守同样规则，不抢 TextBox/聊天/模组 GUI 的输入。
- 允许在 DGR 会话前景中打开设置/记录；保留当前句子、选项、滚动和正在展示的内容。
- 返回时只恢复前景，不发送 Continue / Choice，不重播配音，不重新发送 Start。
- 顶层优先级仍是死亡/退出等原版关键界面；历史/设置不能遮住重生按钮或禁止登录聊天。
- 对话记录按钮点击必须 `handled`，不能因为现有“任意左键继续”逻辑顺带翻到下一句。

## 6.6 配置保存边界

延续 `DarkGreyRPG/Config/darkgrey-rpg-windows.properties` 与现有窗口设置服务。增加字段时保留旧值及未知字段；损坏/越界字段逐项回默认，不删整个配置。

主题/字号/音量是**玩家本地偏好**，不进入 DGRS，不上传为服务器强制配置。“恢复默认”不能清除历史、追踪任务身份、Story cursor、玩家选项或任何世界 SavedData。

# 7. WP-B：任务追踪、进度呈现和已完成任务

## 7.1 Tracker、Toast、任务菜单的职责

| 界面 | 负责 | 不负责 |
|---|---|---|
| 追踪 HUD | 持续显示已追踪任务及 ACTIVE 目标的当前状态 | 不推动任务，不因计数变化播放通知动画。 |
| 右上 Toast | 接取、激活目标、目标完成、任务完成/失败等结构变化 | 普通计数变化、初始同步、重连恢复不发卡。 |
| I 任务菜单 | 全部可查看的任务、追踪操作、详细说明与已完成记录 | 不远程提交物品，不重新领取奖励。 |

**不新增“每捡一次物品弹窗”的系统。**捡到任务物品导致持有数变化，由追踪数值更新；只有造成目标完成/新目标等结构变化时，现有 Toast 正常出现。

## 7.2 追踪操作

用户已确认：最多 3 个 Task。I 菜单对每个可追踪任务显示“追踪 / 取消追踪”，并显示当前占用如 `已追踪 2 / 3`。

- 真正新接任务且少于 3 个时自动加入。
- 追踪已满时新任务正常接取，不顶替旧任务。
- 手动追踪第 4 个时提示“最多可同时追踪 3 个任务，请先取消一个已追踪任务”。
- 任务完成/失败/实际移除时解除追踪。
- 手动取消后，不在每次快照更新时自动加回来。
- 某任务结束释放空位，不擅自把某个旧未追踪任务补入；新的真实接取事件仍可填空位。
- 初始同步不是“新接任务”。优先恢复有效的本地追踪选择；不能把登录时所有旧任务当成新接取并弹卡。

追踪身份至少区分服务器/单人存档、玩家、Story 实例、Task placement 与运行代次，不能只用 Task 资源显示名作为 key。重复 Story 的旧已完成实例不能污染新一轮追踪。

实施默认：追踪选择作为本地偏好持久化，服务器负责提供其引用的任务真实状态。加载时先与当前服务端快照核对；仅删除失效选择，不修改服务器任务。

## 7.3 HUD 布局

默认在屏幕**右侧中部**，参照计分板位置，不靠近右上 Toast。无追踪时完全隐藏。

每个任务包含任务名、分隔、全部 ACTIVE 目标；不展示未激活目标，不塞任务长说明。目标名正常换行，不能用 `...` 隐掉关键条件。多个目标按现有作者/投影顺序排列。

实施要求：

- 检测原版计分板占位，有限向左/向下避让；不声称可以识别所有第三方 HUD。
- 普通游玩时仅绘制，不抢鼠标、滚轮、世界交互。
- 数据无变化时复用排版；不能每帧重读文件、全量扫描背包或发网络请求。
- 所有计数、当前目标的显示来自同一权威只读投影，HUD 和 I 菜单不能各算一套。

### 完整目标与小屏幕冲突的处理

“全部 ACTIVE 目标”是数据与访问承诺，**不得实现为只取前三项、自动丢弃后续目标、或悄悄取消追踪**。

有限屏幕无法同时放下任意多行。工程处理应先换行、调整任务间距和可用列宽；极端溢出使用完整列表的可滚动视口，明确可见滚动条/剩余条数，不隐瞒后面还有目标。I 菜单打开时提供指针进行滚动；普通世界画面不劫持滚轮。完整任务详情始终可在 I 菜单读到。

不要以自动轮播替代全部目标，也不要缩字到不可读。验收须包含 1 个 Task 超过 10 个 ACTIVE 目标、3 个 Task 同时追踪、大字号/大 GUI Scale，证明内容不是被截掉。正常常见目标数量应直接完整展开，不以极端方案替代正常布局。

## 7.4 计数与“持有”的区别

| 目标类型 | 追踪显示 | 完成语义 |
|---|---|---|
| 实体击杀 | `进度 2 / 3` | 服务器确认的有效击杀数。 |
| 物品收集 | `持有 7 / 10` 或统一可读的 `7 / 10` | ACTIVE 时检查当前背包；达到需求就完成，之后不回退。 |
| 物品提交 | `持有 7 / 10`，并说明提交角色 | 持有不是完成；必须与目标角色交互并成功扣除。 |
| 角色交互 | 目标文字 | 不显示没有数量意义的 0/1。 |
| 区域到达 | 目标文字 + XYZ | 不向玩家显示 Dimension ID 或 radius。 |

**新增显示字段不能复用并篡改 Runtime 的 `progress`。**当前提交目标的已提交数在完成前仍可能为 0；应有单独的只读 `held_count`/等价投影。它来自服务端按现有 Item/Group 精确/模糊规则计数，不由客户端自行判定完成。

需要数值的目标即使 `required=1` 也可以显示 `0 / 1`；是否显示依据目标类型，而不是简化成 `required > 1`。

库存减少时，尚未完成的收集/提交持有显示可以减少；已完成收集不回退。提交成功后显示完成状态，不因物品扣除变成“提交失败 0/10”。一次快照更新应先形成一致投影，再送到菜单/HUD/通知。

任务处于“阶段奖励待发、背包空间不足”时保留已有提示，不因为暂时没有 ACTIVE 目标就错误取消整个任务。

## 7.5 已完成任务记录

在 I 任务菜单加入进行中 / 已完成分类；既有失败状态如需显示，采用同一菜单的清楚状态标记，不新造窗口。

首先复用当前 Task Journal、状态快照、结算时间等服务端持久数据。只读列出任务名、任务说明和已经发生的结果，不读取未来/未激活目标来补文本。

重复任务的实施默认：同一逻辑任务可以分组显示完成次数及最近完成摘要，避免无限重复占用菜单；不能删除原有奖励收据或重置游戏状态来实现界面归组。若现有 reset 会丢弃需要展示的完成信息，只增加最小只读完成摘要，在真实结算时生成，不复制整个 Task Runtime 成第二套账本。

**已完成任务记录不是临时对话记录。**关闭客户端清理 Backlog 时不得清除此处依赖的服务器任务状态。此菜单没有“重做并领奖”按钮。

## 7.6 事件顺序与 Toast 不回退

保留结构通知的事件标识、实例身份、合并/去重和终态清理。目标从 `2/3` 达到 `3/3` 并激活下一目标时，同一任务最多更新成一张合并结构卡，而不是“计数卡 + 完成卡 + 新目标卡”三连。

结构卡可显示相关计数快照，例如完成时 `3/3`，但不要把 `held_count` 每次变化转成 Toast 事件。重连、主题变化、追踪开关也不是任务结构事件。

### WP-B 验收

覆盖 0/1/3/4 个任务、手动取消、真正新接、初始同步、跨维度、同服重连、不同服务器、循环任务新代次；计数增减；提交足量但未交；完成和奖励待发；全部 ACTIVE 目标及小屏溢出；Toast 无普通计数噪声。

# 8. WP-C：对话记录与长选项

## 8.1 对话记录的角色

界面名为“对话记录”，入口按钮“记录”。它记录 DGR 实际展示的台词和已确认选择的阅读副本，**不是接管原版聊天记录，也不是新的剧情日志数据库**。

每个上下文最多 250 条，先进先出，纯客户端临时内存；退出 Minecraft 进程自然清空，不必创建临时文件。第一版保存姓名、可读文本、必要的内部去重信息即可；不保留媒体句柄、头像纹理、语音缓存所有权或可执行节点对象。

## 8.2 上下文：服务器 / 单人存档，而不是 Dimension

```text
同一个客户端进程
├─ 单人存档 A 的历史（所有维度共用，最多 250 条）
├─ 单人存档 B 的历史（独立，最多 250 条）
├─ 服务器 A 的历史（所有维度共用，最多 250 条）
└─ 服务器 B 的历史（独立，最多 250 条）
```

- 主世界→下界→末地→Mod 维度：同一份历史，不能清空。
- 断线/回标题再进入同一个服务器：恢复该历史。
- A 服务器→B 服务器：显示 B，不显示 A；返回 A 时 A 仍在。
- 单人不同存档不能混；客户端关闭后全部清除。
- 切换账号时也要隔离，不能把另一玩家的临时记录显示给当前账号。

优先复用现有连接/存档上下文标识。多人以稳定的用户连接服务器标识（规范化 host/port，或已存在的服务器身份）为基础，不使用显示名、会话临时 transportId 或维度号。单人用实际存档身份，不用“主世界”显示名。不要为了历史单独修改世界身份体系。

**禁止把历史清理接到 `theWorld` 对象变化、每次 GUI 关闭、Session END 或统一媒体 `clear()`。**这些生命周期不同。

## 8.3 什么时候记录

历史必须由已经接受的会话帧与实际呈现产生，而不是遍历 Story/DGRS 文本。预加载后续句子/关联故事不等于读过它们。

实施模型：为当前正在展示的一句建立一条记录，随已显示文字更新；全文显示完成后定稿。打开记录不能提前看到尚未逐字展示的尾部，也不能让当前行被每帧 append 成几百条。断线于半句时保留已显示部分；恢复时更新对应记录。

去重依据稳定运行身份和页身份，而不是全文字符串：

```text
上下文 + 玩家 + Story run / Session instance
+ node_id + page_id（或稳定页标识）+ 本次播放序号
```

实际采用现有可获得的字段；如跨重连临时 transportId 改变，不能把它单独当作历史身份。需要补充只读显示标识时做窄协议扩展，不改变 Choice/Story 的执行语义。

同一句在新一轮 Story 里再次真实播放，应生成新的记录。一次重同步、GUI Scale 变化、打开/关闭设置，不得重复记录。

玩家选择记录只在**服务端确认接受该选择**后添加，例如“我选择：……”。点击后被拒绝、过期或取消，不能留下假的已选择历史。只是阅读副本，不能用它作为恢复剧情分支的依据。

## 8.4 入口与操作

- 会话上增加小型“记录”按钮，与继续和选项命中隔离。
- 原版控制设置中注册“对话记录”动作，默认未绑定。
- 无会话时，已绑定快捷键仍能打开当前上下文历史。
- 打开后是只读滚动列表；姓名、台词、选择副本有清楚层级；长文换行。
- 关闭回到之前界面/当前会话，不回退、不继续、不重新播放语音。
- 记录窗使用当前主题和文字大小；不复制/修改原始 `pages` 内容。
- 没有历史时显示空状态；不从服务端全量拉取“以前所有剧情”填满窗口。

## 8.5 与真正玩家数据的硬隔离

```text
客户端历史清空
≠ Choice 结果清空
≠ Story 重启
≠ Task 进度清空
≠ Reward Receipt 清空
≠ 已完成任务档案清空
```

任何清理函数只释放历史集合，不调用服务器的 reset、cancel、discard、complete、resume 或资源卸载接口。用于历史的只读选择文本不能成为奖励或剧情判定的输入。

验收必须比较清历史/关客户端前后权威快照，证明已选择路线、已完成目标、已发奖励均保持。不能只测“历史列表变空”。

## 8.6 长选项

删除“固定 20 高 + 截断为省略号”的正常策略。每项先按可用宽度排版，再计算按钮高度；绘制、Hover、键盘焦点与点击命中使用同一组矩形。[S07]

要求：

- 中文、英文长词、显式换行、格式符都能完整显示。
- 选项按稳定 option/port 身份触发，不能因换行/分页使序号映射错误。
- 内容总高超出可用空间时，按实际高度滚动或分页；保留对话及最后一句头像。
- 单个选项特别长时，也必须能在选择前完整阅读；不能把全文只藏在 Tooltip。
- 支持清楚的键盘焦点与确认，沿用用户按键体系；不要硬编码 T/Enter 覆盖聊天绑定。
- 滚动、移动焦点、查看记录和补全文字不发送 Choice。
- 保留服务器等待期间禁用重复提交，以及现有播放序号防重。
- 前景与上层 GUI 下方的只读会话投影共用布局；不能底层仍用旧按钮尺寸。

### WP-C 验收

多句翻页、半句打开记录、点击补全、相同帧重复、选择确认/拒绝、Story 重复运行、250/251 条；主世界↔下界↔末地；断线重连；A→B→A；单人存档隔离；关闭进程清空但权威状态不变；多行/超长/多页选项以及字号变化后点击同一选项。

# 9. WP-D：Studio 折叠、分组框和精确搜索

## 9.1 多句台词的外层折叠

标题行按以下固定顺序：

```text
展开：  ⋮⋮  第 1 句  ▲                              −
折叠：  ⋮⋮  第 1 句  ▼                              −
```

- 三角位于“第 1 句”右边，不放最左，不使用右三角。
- ▲ 的动作是收起，▼ 的动作是展开。默认每句展开。
- 折叠隐藏本句正文和“本句设置”等全部内容；拖动手柄、句序、三角、删除仍可操作。
- 已有“本句设置”内部默认折叠逻辑保留；外层展开不强迫所有设置都展开。
- 新增句子默认展开并聚焦正文；至少保留一句的规则不改。
- 节点本体与 Inspector 共用句卡组件/状态，不做两套字段编辑。

折叠状态按稳定 `page_id` 关联，不能按“第几句”数字关联；排序后同一句仍保持自己的状态。它是 Studio 编辑状态，不进入 `pages`、DGRS、Runtime 或玩家存档。实施默认：同一次 Workspace 生命周期中记住，重新打开应用默认展开；不需要专门落盘。

折叠不能改正文、清除语音、把资源视为不再使用；不能制造业务 Undo。排序、删除仍走已有一次手势一次撤销机制。折叠引起节点高度变化后，端口/连线/命中区域必须在布局完成后刷新，防止重新引入 Ctrl+Z 连线错位类问题。

测试包含：10/50 句、一句长文、两侧切换、折叠后拖排序、折叠时删除、撤销恢复、正在编辑时折叠、节点切换和保存重开。读/写 `pages` 内容在只折叠前后必须完全一致。

## 9.2 分组注释框：编辑辅助，不是 Runtime 节点

采用成熟节点编辑器的 Frame / Comment 思路：半透明矩形底板、低饱和细边框、顶部标题，位于节点与连线后方。Godot GraphFrame 的成员附着、整体移动及后景渲染可作为交互参考；这里只借鉴模式，不引入 Godot 依赖。[E01]

适用当前 Story、Session、Task 和项目图谱。Project 中 Frame 也只是布局元素，不能绕开实际 Story 创建规则。

第一版行为：

- 选中节点后“创建分组框”，初始尺寸包住选中节点；也可在空白处创建空注释框。
- 标题可编辑，用于注释如“调查阶段”“隐藏分支”。不需要用户输入 FrameID。
- 拖动标题/边框整体移动框及明确成员节点；本次移动组成一个撤销操作。
- 调整框边缘大小只改框矩形，不缩放内部节点，不自动改变成员关系。
- 删除框只移除注释和分组，**不删内部节点、不删连线、不删资源**。
- 成员加入/移出采用明确操作；框经过/覆盖别的节点不自动把它吞进来。
- 一节点只隶属一个分组；第一版不做嵌套分组，避免双重移动和循环归属。
- 框内部透明空白不拦截节点点击、端口拉线、画布平移和框选。

成员关系保存在 editor layout metadata 中，使用已有 node 身份。跨图不混用；删除成员节点清理对应引用；撤销恢复；重命名资源不丢布局。相关布局写入使用原有安全保存体系。

复制节点时保留现有深复制规则。显式复制整个组可以连同其成员与布局复制，内部节点 ID 映射同步到新组；只复制几枚节点时不能把旧组中没选的节点一起带走。参数粘贴不复制分组身份。

**Frame 无 Flow/Logic 端口，不出现在 Runtime 节点注册表，不进入 DGRS 执行图。**只有分组布局变化时，原有剧情图的语义内容和运行行为不得变化。

视觉验收：Studio 深/浅主题、不同缩放、长中文标题、重叠框、选中/未选中；不做高饱和整块遮挡，不铺大块纯色，不盖住端口和连线。

## 9.3 精确搜索定位

在现有搜索/资源导航上扩展，而不是平行创建第二个搜索窗口或网络索引系统。

支持项目内：Story/Session/Task 名称、节点标题、目标描述、任务说明、每句台词、选择文字、分组标题，以及角色/物品/媒体的引用位置。搜索已加载的未保存编辑也要有正确结果，不能只读磁盘旧版本。

台词结果示例：

```text
第二章 > 酒馆会话 > 台词「老板」 > 第 4 句
“……关键词……”
```

结果内部保存稳定定位：资源身份、node_id、page_id / option_id 与所属/引用路径。句序仅展示，不作为持久地址。点击结果后：

1. 打开对应 Workspace / 图。
2. 定位并居中正确节点。
3. 选择对应句/条目，必要时展开这一句和相关容器。
4. 将文本编辑区滚动到命中处，不发送业务修改命令。

同一 Session 被多个 Story 引用时要说明是共享资源及引用位置，不把多条结果伪装成独立副本。只读引用仍只读；导航不偷偷改成 owned resource。

工程要求：中文子串、英文大小写处理一致；匹配摘要正确转义；防止过期异步搜索覆盖新项目/新关键词；按项目/资源修订增量刷新。第一版不做语义搜索、云服务、AI 索引或搜索替换。

### WP-D 验收

折叠完整矩阵；Frame 创建/移动/尺寸/删除/撤销/保存/复制；Frame-only 变化不污染运行图与导出；多句排序后搜索仍命中原页；共享资源多路径、未保存文本、只读引用、切项目期间搜索、长中文标题和缩放实机。

# 10. WP-E：环境留声机方块与个人播放

## 10.1 产品定位和权限

新增“环境留声机”可放置方块及对应物品，用作地图/服务器创作工具。第一版不做生存合成、经济系统或普通玩家解锁流程。

- **放置、拆除、配置：OP 或创造模式。**服务端每个写入动作都检查，不能只灰掉客户端按钮。
- 普通玩家无需权限即可听到有效范围内的音乐。
- 权限在 GUI 打开后被收回，保存/删除仍应被拒绝。
- 防止生存破坏、爆炸、活塞搬运、可检查的自动化路径绕过正常保护；与现有服务端保护事件协同。
- 不承诺对任意 Mod 绕过事件直接改世界的行为都不可破坏，但失去方块后的清理必须可恢复。

它是 DGR 自己的方块，定位可以使用世界/维度/坐标及内部实例令牌。禁止让作者为其指定通用 BlockID；不能由此扩展任意 Mod 方块身份系统。

## 10.2 配置界面

使用同一套游戏主题和窗口风格，主要区块为：

```text
环境留声机

播放开关     受红石信号控制
播放范围     显示范围

来源：在线 / 本地
  在线：QQ音乐 / 网易云，歌曲或分享链接，解析结果/本地试听
  本地：导入，波形/进度，本地试听

导入（本地模式）     保存     删除
```

文字是布局示意，不要求把所有控件塞一行。在线为主模式、本地为备用入口，但本地不能被隐藏到无法使用。

新放置没有媒体时不播放。保存成功后按已保存播放开关运行。普通玩家只听，不应弹出可编辑配置。

“显示范围”只在配置者客户端绘制虚拟立方体线框；不保存成可见世界实体，不给所有玩家发粒子，不长期每 tick 扫描大范围世界。

## 10.3 范围与重叠

使用与 DGR 区域目标一致的方块坐标定义：

```text
bx = floor(player.posX)
by = floor(player.posY)
bz = floor(player.posZ)

同一维度
且 abs(bx - gramophoneX) <= R
且 abs(by - gramophoneY) <= R
且 abs(bz - gramophoneZ) <= R
```

R 是非负整数；负坐标正确 floor，不能直接强制转 int。以方块格计数，包含边界时每边覆盖 `2R+1` 个格，预览框的几何边界必须与实际格区一致。中间计算避免整数溢出。

默认半径可先采用 16 格；最大值作为工程安全常量在性能验证中确定，超限明确报错、不静默截断。不是新增玩家设置页面。

范围内使用恒定音量，不随着离中心远近衰减。**多台范围重叠全部播放**；不选最近、不排序选一台、不因播放相同指纹而合并为单一音源。

设备发现/状态同步使用已加载设备索引与事件更新，不强制加载周围所有区块，不每玩家每帧遍历所有世界方块。范围覆盖的必要设备信息必须可用；方块区块卸载后的行为见下节。

## 10.4 服务器共享配置，客户端个人进度

服务器同步：位置/内部实例、配置修订、媒体来源、范围、播放开关、红石控制及当前通电状态。**不同步所有玩家必须一致的歌曲秒数。**

每位玩家针对每台有效设备持有个人播放器。A 先进入、B 五分钟后进入，B 从头；A 的播放不改变。每台设备独立淡入淡出，分享缓存不分享播放进度。

第一版作为环境 BGM 循环播放；不开发歌单或播放队列。循环续播不能重新创建网络资源和积累音源。

## 10.5 播放生命周期表

| 条件 | 行为 |
|---|---|
| 首次进入有效范围且允许播放 | 资源可用后从头播放并短淡入。 |
| 持续位于范围内 | 恒定目标音量，当前播放时间正常推进。 |
| 走出边界 | 从当前音量短淡出，结束后停止并释放个人播放实例。 |
| 淡出尚未完成就折返 | 保留实例和当前位置，从当前音量平滑反向淡入。 |
| 已完全淡出后再次进入 | 新个人实例，从头播放。 |
| 红石控制开、从有电变无电，玩家仍在范围 | 暂停；保留个人播放位置，时间不继续推进。 |
| 从无电变有电，玩家仍在范围 | 恢复原个人位置，不从头播放。 |
| 无电时新玩家进入 | 不发声；之后首次通电从其个人开头开始。 |
| 暂停中玩家离开范围 | 释放个人实例；以后回来仍按重新进入处理。 |
| 播放开关关闭 / 删除音乐 | 淡出并停止，不擅自恢复旧音乐。 |
| 保存替换新曲 | 旧曲平滑退出，新曲按个人新播放处理；保存失败旧曲保持。 |
| 设备被移除 / 其区块卸载 | 撤销播放拥有者并清理；有条件时淡出，不留幽灵音乐。 |
| 跨维度 / 断线 / 退出存档 | 释放当前世界音源及请求；不影响别人的播放。 |
| 客户端退出 | 关闭解码器、音频流、句柄，释放临时缓存所有权。 |

红石不新增“通电从头播”的选项。留声机进入/离开淡入淡出可先用固定短值（例如约 0.6 秒），最终按实机听感调整；不增加玩家可配动画参数。

**红石暂停与离开区域是两个不同原因。**不得用统一 stop/recreate 把二者都实现成重头；也不得为了保留暂停位置而让玩家离开后还永久保存每台设备时间。

## 10.6 音频后端

可复用 Minecraft 已有音频引擎和 DGR 小型播放服务，但留声机的 source key 必须区分上下文与设备实例。不能复用单一 `dgr_session_music` 通道覆盖会话，也不能一台设备 stop 清空全部留声机。

文件按指纹复用，播放/暂停/淡入淡出属于实例。不影响原版音乐或外部点歌插件，不调用全局 stop-all。

多个设备同时播放仍须控制 I/O 并发、文件句柄和解码缓存。**工程队列上限不等于“只许一台/三台留声机发声”**。资源耗尽时明确诊断并保障客户端不崩溃，不能把静默挑选某台包装成用户确认过的功能。

### WP-E 验收

同/异维度边界、负坐标、R=0、可视框一致；多台不同曲/同曲重叠；两玩家错时进入；离开/立即折返/完全离开再返；红石快切/长暂停；配置替换、方块拆除、区块卸载、玩家断线；无权限与权限撤销；不影响 Session 或原版声音。

# 11. WP-F：QQ / 网易云接入、本地上传与媒体生命周期

## 11.1 在线支持范围已定，技术可用性必须实证

首批产品范围是 **QQ 音乐 + 网易云音乐的公开可解析单曲/分享链接**。不做账号登录、凭证保存、站内搜索、歌单或会员歌曲保证。URL 能提取 song key 不代表音频能播放，更不代表取到的是整首而非试听片段。

**本 PLAN 没有核实出一个可直接无凭证覆盖两平台全部歌曲的官方通用 API。**本轮查到的腾讯官方音乐 SDK 属于其指定集成环境，部分能力要求授权；不能把该文档当成 DGR 已获得匿名播放接口的证明。[E02]

施工必须先为每个平台完成最小闭环：

```text
真实公开分享链接
→ 规范化平台与单曲标识
→ 取得当前实际允许的音频来源
→ 在 Java 8 / Minecraft 1.7.10 实际后端解码并发声
→ 暂停 / 恢复 / 重入
```

分别记录测试日期、所用官方或第三方实现来源、依赖许可、访问条件、公开曲样例、格式、试听限制、URL 失效与错误行为。不能只记录“HTTP 200”或“播放器对象建立”。

这属于外部依赖验证，**不是重新询问用户要不要 QQ/网易云**。两者均在范围内；不能静默删掉一个、伪造成功、用本地文件冒充在线、或要求用户额外部署服务而不说明。

若目标平台在无登录范围下确有阻塞，保留可验证的失败原因，继续其他不受影响工作，但该平台和整体在线交付不能标为 PASS。新限制必须明确报告，不用一个长期空实现宣称“已支持”。

## 11.2 来源抽象与存储

在线来源建议使用一个小型接口和两个适配器，不做插件市场或泛化媒体平台。数据概念：

```text
OnlineSource
  provider = qq | netease
  track_key = 平台实际单曲标识
  canonical_share_reference
  display_metadata（非身份依据）
```

平台曲目标识是第三方来源信息，不是新 DGR MusicID。普通作者只粘贴链接，不必管理这些内部字段。

服务器保存设备配置和来源描述；每位客户端独立解析/接收允许播放的媒体并维护自己的进度。可复用短时解析结果，但**不能把临时签名播放 URL 永久写进方块 NBT 当作唯一来源**。

在线正常路径不要求服务器代传整首歌。运行过程中客户端仍需接收数据、解码、缓冲或受控临时落盘；不得宣称“在线播放零下载、零内存、零缓存”。

第一版不把在线媒体打进 `.dgrs`。线上不可用时明确显示不可播放/当前不可用，不自动替换成另一首歌。

## 11.3 链接、安全与错误

- 只解析声明支持的 QQ/网易云单曲与分享链接；短链仅在受控重定向解析后接受。
- 解析器/客户端媒体下载不能是任意 URL 代理。阻止 `file:`、本机/内网地址、路径穿越、无限重定向，以及重定向后的越界目标。
- HTTPS 使用正常证书校验，不通过关闭 TLS 验证解决老 Java 网络问题。
- 不导入浏览器 Cookie、不记录登录令牌、不将玩家或管理员凭证发给第三方。
- 请求有连接/读取超时、响应大小、并发和重试上限；失败不在每 tick 重试。
- 404、下架、需要登录、会员限制、地区限制、网络超时、非音频响应分别给可读提示；不伪装成播放成功。
- 若平台只返回试听片段，必须明确标为试听，不能把片段循环冒充整首 BGM。
- 解析结果切换设备/配置后返回，必须按实例与配置修订丢弃过期结果。

上述是输入与稳定性约束，不是做完整的账号/商业音乐客户端。

## 11.4 音频格式与暂停

现有 Session 音频主链面向项目缓存中的 OGG/Vorbis。[S13] 网络来源可能返回不同格式，**不能把 MP3 URL 改个 `.ogg` 后缀当成已兼容**。

实现前验证实际返回的每种支持格式。优先采用许可明确、体积合理、可在 Java 8/现有引擎使用的解码方案；不替换 Minecraft 整套声音后端，不隐含要求每个玩家手工安装外部转码程序。

本地导入可以复用已有媒体工具或明确随包交付的转换链，转换为现有游戏播放副本。在线流若为确保暂停/恢复需要有界临时文件或缓冲，应由客户端媒体层处理，不把整个音频永久留在 heap。

红石长暂停后，播放位置必须仍属于该个人实例。连接或临时 URL 过期时可重新解析并按已保存位置恢复；无法恢复则说明资源暂不可用，不能无声从头播放来掩盖不满足 Pause/Resume。此路径是两平台实证必须覆盖的项目。

## 11.5 本地备用：草稿与已保存音乐分离

本地配置操作固定为：

1. **导入**：读取配置者本机选中文件，验证/转为游戏播放副本，显示波形或音频包络、进度条、播放按钮和时间。
2. **试听**：只在配置者客户端播放；可拖动进度，不广播给其他玩家，不更新服务器设备。
3. **保存**：先询问是否保存并上传；只有确认后才开始必要上传。
4. **删除**：清除这台留声机已保存来源，停止其播放并解除该设备的持久引用；不是全服删共享音频。
5. **未保存退出**：按 ESC、实际背包键或关闭窗口，停止试听并释放草稿；服务器仍保持原音乐。

连续导入 100 首试听后仅保存最后一首，服务器不得收到前 99 首音频。源文件允许较大，但不能无界读入内存；运行副本仍受明确大小/时长/解码限制。限制在转换前后给出说明，不能把旧讨论的源文件大小机械当作压缩后大小。

若本地副本与已存在内容指纹相同，先由服务端确认是否可复用，避免重复传整个文件。该确认不能变成任意下载其他创作者媒体的入口。

## 11.6 上传事务

服务器收到保存请求时重新验证玩家权限、距离/目标设备、实例令牌和配置修订。

```text
确认保存
→ 申请受控上传会话
→ 有界分块写临时文件
→ 校验长度、指纹、音频容器/可解码性
→ 原子安装唯一 blob
→ 原子提交该设备的新媒体引用/配置
→ 再释放旧引用
```

不完整、超限、损坏、被取消、设备已被拆除、权限撤销或目标配置已变化时，不替换旧音乐。不能“先删旧曲再等上传”。临时文件属于已知上传会话，可在超时/异常启动时安全清理。

多位 OP 同时编辑同一设备时使用修订冲突检查；后提交者收到当前配置已变化的提示，不能覆盖别人刚保存的数据。客户端包不能通过伪造 Source/路径绕过权限。

## 11.7 服务端持久引用与回收

本地音乐使用按内容指纹去重的服务端媒体存储。建议目录在统一根中独立于 StoryPackages：

```text
DarkGreyRPG/
├─ StoryPackages/                         用户故事包，不变
├─ Media/Gramophone/<存档键>/             本地上传的权威媒体
├─ Cache/Gramophone/...                   可重建/临时数据
└─ Config/...                            本地偏好与必要工程配置
```

这是本版新媒体领域的目录建议；实际路径应服从现有统一路径服务和明确外部配置。设备配置/引用索引必须随对应存档正确保存与备份；不能只备份世界 NBT 却遗漏唯一的音乐文件而不说明。

引用模型：

- 多台设备使用同一指纹 → 一份 blob，多个持久所有者。
- 删除/替换一台设备 → 只解除这台的持久引用。
- **区块卸载、玩家离开、客户端断线不解除方块持久引用。**
- 持久引用为 0、无上传/传输/播放相关临时 pin，并经过延迟宽限期 → 才允许回收。
- 重新加载区块时沿现有索引恢复，不把未知的未加载设备当成“不存在”。
- 异常退出后通过保存的事务/引用索引恢复；不靠扫描“当前加载区块”推导全世界所有引用。
- 操作只限程序管理的目录/文件；不递归删除未知文件、符号链接/重解析点或用户故事包。

使用现有小型事务/所有权方案能解决的地方就复用，不为此引入外部数据库、守护服务或复杂治理系统。

## 11.8 客户端缓存与线程

共享内容文件可以复用，所有者至少区分下载、试听、设备播放器。只有最后使用者释放才可删。缓存与服务器/单人存档命名空间隔离，不能跨服信任一个未经当前校验的文件。

本版不改变故事的“10 包 / 3 并发”。留声机音频不是故事包，使用独立的有界临时/短缓存策略，复用底层指纹验证和磁盘 I/O；不能假造一个 Story 占故事缓存名额。

工程默认：活动音源与上传/解码 pin 受保护；无引用文件只做小型最近使用保留，超过有界额度按 LRU 清理；正常退出清理不再需要的临时音频，异常启动回收残留。具体文件数/字节/并发上限在 `TECHNICAL_DEFAULTS.md` 写入并验证，不留无穷大或仅有 TODO；不新增玩家可调参数。

必须有源文件/运行副本单体上限、总空闲缓存预算、HTTP 响应上限和 Worker 队列上限。不能只写“最后会 GC”却在运行十小时中无限增长。

网络解析、转码、解码、音频波形、哈希、文件读取均不阻塞客户端渲染或服务端 tick。主线程做权限/世界状态检查，异步处理 I/O，返回主线程时再次确认归属；音频源/纹理操作遵守实际引擎线程要求。

### WP-F 验收

QQ 与网易云分别：公开单曲/分享短链、有效播放、真实听音、不能播放的歌曲、试听片段识别、URL 失效、超时、暂停恢复、离开再入、两客户端。

本地：大量导入只试听、不保存退出、确认后才上传、同指纹去重、失败保留旧曲、并发编辑、拆除期间上传、区块卸载保护引用、最后引用延迟回收、磁盘满和异常重启、网络截断和缓存篡改。

## 12.3 兼容和数据改动范围

## 12.4 性能和资源保护

- 无每帧配置写盘、全项目搜索重建、所有世界方块扫描或服务器任务请求。
- UI 文本布局按内容/字号/宽度/主题必要修订失效，不无条件重建业务模型。

| 在线输入 | 两平台规范化、分享短链、重定向安全、非音频/过大响应、受限/试听/失效、取消与修订。 |
| 本地草稿 | 连续导入只试听、不保存无上传、确认上传、失败旧数据保持、退出释放。 |
| 媒体所有权 | 同指纹共享、最后引用延迟、区块卸载不删、播放pin、上传pin、替换与异常恢复。 |
| 磁盘/网络异常 | 磁盘满、断流、缓存损坏、临时残留、符号链接/重解析点、取消期间完成回调。 |
| 线程/资源 | 有界请求、main thread无重I/O、播放器/句柄释放、反复进入退出不持续增长。 |

新测试名称可采用 `...0332...` 区分。具体 task 名称必须登记到实际构建文件，不在文档中写一个不存在的命令然后声称跑过。

## 13.3 Codex 必须执行的同包端到端路径

使用独立、可删除的测试项目/存档，不使用用户实际工程或长期服务器存档做破坏性测试。

### E2E-A：Studio 正式导出

在实际打包后的 Studio 中创建或编辑测试项目，至少包含：

- 2 个相连 Story，覆盖 Flow/Logic 入口与非重入。
- 多句台词、不同表情/语音、全局与自定义速度。
- 一个很长选项和一组多项选项。
- 标题等待与不等待各一处。
- 三类计数目标、交互、区域到达，提交对象与物品真实绑定。
- 至少 4 个可接任务，其中有多个并行 ACTIVE 目标及一个奖励待发案例。
- Frame 和搜索定位，折叠/排序/保存重开。

用 Studio 正式导出 `.dgrs`。记录路径、生成时间、SHA-256 和源码/EXE 版本。**禁止随后手工改 JSON 或注入资源再将其称为同一个导出产物。**要修夹具就返回 Studio 修改并重新导出、重新记录哈希。

### E2E-B：真实 Minecraft 加载

把该同一文件复制到独立 Minecraft 的 `DarkGreyRPG/StoryPackages`，复制前后 SHA-256 相同。加载本版 JAR，实际完成 NPC 交互、台词翻页/补全、选择、提交、区域到达、任务推进与跨 Story。

验证：任务追踪选择/实时进度/Toast；三主题/字号/透明度；对话记录；跨维度和重连历史；完成记录；设置改键与上层返回。真实输入和运行结果记录，不能只直接设置 GUI 字段伪造操作。

### E2E-C：留声机

实际放置两台以上设备，配置重叠立方体范围；分别使用本地与在线来源。用真正的客户端试听、保存确认、播放、红石通断、离开/折返/重进测试。

本地连续试听多曲未保存时，服务端新增上传量应为 0；最终保存仅传最终副本。两台共享同曲时资源去重但两台的个人播放实例独立。

### E2E-D：独立服务端 + 两客户端

环境留声机是多人功能，不能只以集成单机验收：

- 两玩家不同时间进入，分别从自己开头播放。
- A离开/断线/调整音量不影响B。
- 红石共同变更，两位玩家分别从自己的暂停位置继续。
- 普通玩家无法修改、拆走或伪造上传。
- 同服跨维度对话记录不断，跨服不混。
- 设备替换/卸载和网络延迟下无旧音频/旧回调污染。

### 真实声音验证

音源状态、时钟与解码日志是必要证据，但不等于听感。淡入淡出、无距离衰减、红石暂停/继续、音量类别、重叠混音和两平台播放必须有实际听音记录。没有音频输出条件就标未验证，不能写“听感正常”。

## 13.4 视觉质量门

先功能通过→拍截图/录制关键手势→检查→修改→重新拍最终版本。最终布局改动后不能沿用修改前截图声称最终验收。

## 13.5 性能与压力验收

记录环境、样本规模和实测值，不写未经测量的“不卡”“零内存”承诺。

- 一个50句台词节点反复折叠、排序与切换Inspector，连线和输入稳定。
