## B. Understanding

Studio authoring 定义 DGR identity 和资源关系；冻结的 `.dgrs` 把这些定义交给 Runtime。Minecraft 牛、猪、僵尸、原版史莱姆、木棍等只是 Host，本身不等于 DGR identity。Nominator 把真实 Host 显式绑定到 DGR `Group_ID`、`NPC_ID` 或 `Item_ID`；Runtime 只按该绑定解析 Task、Story、Session 和 Action。此 fixture 中“史莱姆”是 Collective Actor `Group_ID=slimes`，Task target 也是 `slimes`，并非 Minecraft `EntitySlime` 类型。

## C. KEEP / FIX / REVIEW

### KEEP

- 保留 B1 的 DGRS direct-read、detached package snapshot 和 last-known-good replacement 行为。

### FIX

- DGRS reader 增加 4096 entries、单 entry 64 MiB、总解压 256 MiB 的预算上限。
- 只清理精确命名的历史 `.dgrs-runtime` 目录，并拒绝 reparse point/link；不删除其他未知目录。
- 删除最后 package 或 base project 无效时安装明确的 empty/unavailable snapshot，不再保留旧资源为 authoritative；同时保留真实 reload failure 状态。
- package 卸载时清除引用已卸载 Story/Session/continuation 的运行实例，避免持久化 cursor 在 tick 中反复重新绑定并刷出 `Missing canonical Story resource`。

### REVIEW

- Story port `order`：冻结 contract 为 direction-scoped order，不要求全局唯一；维持 B1 行为，不修改 Studio。
