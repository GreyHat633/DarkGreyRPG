# 0.4.0.2 Runtime 分数缩放字体采样修正

当前修正版已重新发布，见 [Rerelease.md](Rerelease.md)。以下保留此前阶段的来源、哈希与当时状态。

2026-10-10。对应用户截图中任务通知标签和正文笔画粗细不一的问题。该记录接续 [UiSizeCorrection.md](UiSizeCorrection.md) 的尺寸恢复，之前的 `00D03FC1…` 证据保留为修正前对照。

## 原因与处理

原生 Unicode 字库是位图。尺寸恢复后，通知仍使用原有的自适应倍率，小字再乘 `.85`，标题乘 `1.25`。这些分数倍率配合最近邻采样，会把相同的一条细笔画分别取整成 1 或 2 个屏幕像素；不同字内的横竖笔画也随位置出现粗细跳变。上一次保留了最近邻采样，未解决这个问题。

本次在公共 `DialogueFontDrawing` 入口添加像素覆盖率采样。分数倍率下，根据一个屏幕像素覆盖的原字库区域计算透明度；只采样当前字格，避免邻字串入。采用原字库、原字形四边形、原字号和宽度测量，不添加阴影或第二次文字描边。整倍数的 Unicode 源像素保持原绘制路径。采样使用当前绑定纹理的实际尺寸，英文 ASCII 与中文 Unicode 纹理可在同一字符串内切换。

小字和图谱极小 zoom 的采样也按实际面积计算，没有将采样范围截到八个源像素。循环只遍历像素覆盖区域与当前字格的交集；通常放大时仅需少量采样，缩到小于一像素时最多遍历自身字格。字形四边形仍然受原光栅化规则限制，极小文字不会变成可读的大字。

此次没有修改上一轮恢复后的通知、追踪、按钮、列表、提示框、Title、图谱或窗口布局类。与 `00D03FC1…` JAR 比较，仅公共绘字类及内部 `Filter` 类两个旧条目变化；`Filter` 的指令反汇编完全相同。新增一个采样辅助类和两个 shader 文件，其余已有条目逐字节相同。业务、存储、网络和 Studio 未修改。

## 实测与回归

Runtime build、测试驱动 build 和 42 项版本 Probe 全部通过。字体策略 Probe 遍历 699 个主源码输出类，仍只有一个受控原始绘字入口；JAR 另含生成的常量类，共 700 个 `darkgrey/rpg` 类。正式产品 JAR 不包含测试驱动。

在隔离 Forge 1.7.10 世界运行修正前后两个原生客户端，共记录 14 组对照：GUI 1、2、3、4；关闭 Unicode 的中英文混排；实际通知和追踪 HUD；125% 对话选项。测试文本复现截图中的“开启故事包B”与“与测试员再次对话,开启故事包B”。合成字样页面仅是原生绘字检查，不是业务验收。

从未经缩放的实机截图读取四个相同细竖线的横向灰度覆盖面积，结果如下。单位是等效屏幕像素；灰度覆盖测量包含半透明边缘，不把每个非白像素都算成一条完整笔画。

| GUI 倍率 / 字号倍率 | 修正前四条竖线宽度 | 修正后宽度范围 |
| --- | --- | --- |
| 4 / `.629`，通知小字 | 1 / 2 / 1 / 1 | 1.255–1.259 |
| 4 / `.74`，通知正文 | 2 / 1 / 1 / 2 | 1.478–1.482 |
| 4 / `.925`，通知标题 | 2 / 2 / 1 / 2 | 1.847–1.851 |
| 2 / `1.25`，125% 选项 | 1 / 2 / 1 / 2 | 全部 1.251 |

上述跳变样本的宽度差从 1 像素降至不超过 `1/255` 像素的灰度量化差。GUI 2 的整倍数测试行，以及 GUI 4 的 100% 和 150% 测试行，指定字体区域逐像素相同。比较区域排除了窗口边框和游戏画面外的其他窗口像素。

- 通知不透明内部的实测宽度仍为 557 像素，位置也相同；没有再次扩大通知。
- GUI 2 下的 125% 选项仍为 160×60 GUI 单位、四行、字号倍率 1.25。
- 所有成对用例报告的画面、GUI 和选项尺寸均相同。
- 下划线/删除线所在字符串沿用原绘制，其测试区域逐像素相同；普通红色中英文格式保留。半透明黑字在白底上的最小 RGB 为 127，符合约 50% 透明度。
- 原生日志确认新 shader 编译并使用，纹理采样参数、纹理绑定、混合开关和绘字后 program 恢复检查全部通过。

实机环境为 NVIDIA RTX 2060、OpenGL 4.6。一块显卡上的成功不代表第三方字体包或 shader 模组兼容性验收。OpenGL 3 不可用、shader 编译失败、已有外部 shader、透视世界标签，以及含下划线/删除线格式的整段文字，保留原绘制路径。没有增加用户配置、强制改字号或变更世界标签尺寸。

两个客户端均通过原生菜单退出；隔离服务器正常保存并停止，无关进程未操作。旧 `dialogue0333Probe` 的既有 profile 断言失败仍按上一份记录保留；人工听音和用户延后项状态不变。
