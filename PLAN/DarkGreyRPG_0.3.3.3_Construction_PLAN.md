## 1.2 明确覆盖旧方案

| 旧讨论或当前行为 | 0.3.3.3 最终采用 |
|---|---|
| 固定“最多 160 个字”或按字符类别粗略计数 | 按真实字符显示宽度和自动折行计算**文本容量**；160 仅为示例 |
| 超过显示容量禁止导出 | 红色警告，允许保存与导出；运行时分页兜底 |
| 台词正文允许作者回车换行 | Enter 完成当前编辑；数据中不新增手动换行，视觉自动折行仍保留 |
| 正文超出后提示“鼠标滚动” | 点击左键翻本地显示页，无正文滚轮滚动、无滚动提示 |
| 自动分页生成新作者台词或新节点 | 原 authored page 不变，仅客户端产生 Display Segment |
| 历史随逐字/分屏显示一点点追加 | 原句开始展示后，历史记录**完整原句一条**；不做后半句防泄露 |
| 声音三分类，额外受原版 Music / Players 控制 | 玩家仅“语音 / 背景音乐”；额外只遵守 Minecraft 主音量 |
| 分组靠普通拖入/空间重叠自动增减成员 | 普通拖动只改位置；组合命令或 G 拖动才改归属 |
| 分组需手动拉大小、只能拖标题 | 自动适配内容；组内未被子对象占用的空白可选择并拖动整组 |
| 删除 Frame 一律保留节点 | 选中组后 Delete 删除整个组内容；**取消组合**才保留内容 |
| 不支持嵌套 | 支持组中含组，保持树结构，无循环 |
| C / Ctrl+P / Alt+P 等分组快捷键体系 | 主入口为可见“组合”按钮和 G；不另建一套大量必记快捷键 |
| 留声机关闭 GUI 就停止显示范围、销毁试听缓存 | 范围显示独立保存；关闭 GUI 停试听并释放引用，缓存按策略回收 |

特别说明：最后一次确认中的“没有显式选中 Group 就新建 Group”是简写，若机械执行会覆盖用户已经给出的 **D＋已有组的任意成员 → D 加入该组** 例子。本文 §10.4 将该具体例子写成优先分支，“新建组”仅作其余无唯一目标时的兜底；不让执行者在两句表述之间自行猜测。

# 4. 既有能力与不回退边界

## 4.1 核心运行与身份

- Story ACTIVE 时不能由任何 Start 重入；流程驱动只激活命中的启动条件；可重复 Story 逻辑启动继续遵守 False→True。
- Session / Task / Story 的公开端口、类型语义和稳定身份不改。Task 内仍为纯逻辑图，组不是 Task 节点。
- NPCID、ItemID、GroupID 继续解决 Studio 与世界对象的映射；不把组或媒体内部标识暴露成新的资源 ID 分类。
- 奖励、提交仍由服务端验证和事务/收据保证；客户端文字、偏好、历史、分页不得改变结果。
- 死亡界面、聊天、背包、其他 GUI 优先；DGR 对话下层可见但不可抢输入。Esc 仍交给正常退出菜单，不恢复“挂起会话”功能。
- 【标题】保留当前可选“播放完再继续流程”行为，不倒退成所有标题强制阻塞。

## 4.2 UI、任务与媒体

- 玩家文字倍率保持 **100% / 125% / 150%**；不暗中缩小用户选择来掩盖溢出。
- 多句台词、稳定 page_id、逐句头像/语音/速度、排序及已认可折叠动画保留。节点本体与 Inspector 共用编辑组件。
- 任务最多追踪3个，默认右侧中部；显示全部 ACTIVE 目标，普通数量变化只刷新状态，不增加 Toast。
- 对话历史每服务器/单人存档250条，跨维度与同服重连保留，跨服隔离，退出客户端清空；真实 Choice/Story/Task/Reward 数据不能被历史清理。
- DGRS 仍自包含媒体，磁盘索引/分块读取保留；Story 媒体10包/3并发及运行包保护不变。
- 留声机仍是 OP或创造模式创作工具；立方体范围、范围内恒定音量、重叠全播、个人播放进度、进出渐变、完全离开后重进从头、红石暂停/续播不变。
- 在线支持范围仍是 QQ/网易云可匿名完整播放的公开单曲；本地导入仍是备用，只有明确保存确认才上传。
- 本版缓存修复不允许把整首音频常驻 heap、不允许无限缓存、不允许关窗同时停止别人的设备播放。

## 7.3 文本容量，不是字数（T02–T04）

### 7.3.1 基准规格

施工先完成 §7.1 的布局，再生成一份有限、可审计的 `DialogueCapacityProfile`（建议新增的数值规格，不是新的资源系统），至少包含：

```text
profile_version
标准 FontRenderer 字宽来源和字体模式
设计倍率 = 1.5
支持范围中采用的最小 GUI 逻辑尺寸
有头像/姓名/自动与记录时的实际正文边界
每个可显示字符的 advance 度量及行高规则
容量基准单位 U
RAW_CAPACITY
SAFE_CAPACITY = floor(RAW_CAPACITY × 0.90)
```

最低逻辑尺寸和最终容量必须来自本版正式布局测试，记录物理分辨率、GUI Scale 和得到的逻辑尺寸。不能只写“1920×1080能用”，也不能凭示例直接定160。小于校准支持范围的极端窗口仍要求客户端分页/布局降级安全运行，但不宣称其容量与正常范围一致。

Studio 使用标准字体数值度量；不使用 WPF 当前 UI 字体的宽度代替 Minecraft 字宽。可生成/保存**数值字宽表和测试结果**，不得把字体文件、原版字体纹理或整个 Minecraft 资源打包进施工交付。若运行时存在不同标准字体模式，校准并记录覆盖范围。

自定义字体资源包不属于 Studio 容量保证；不为此建设字体选择/导入系统。运行时仍用实际渲染度量分页，尽量容错，但10%余量不能被描述成可保证任意字体包。

### 7.3.2 字宽到容量的换算

不要按“汉字一律2、字母一律1”硬分种类，也不要每个字单独向上取成粗糙整数后大量损失容量。内部保持真实 advance 或足够精度的定点数，只在显示累计容量时保守取整。

字母 `i/l/W/m`、标点、数字、全角/半角空格等都按真实宽度计。用户举的 `Hello=5、你好=4` 是解释容量概念的**假设示例**，不要求实际 Minecraft 字体强行得出该数值。

一般等宽正文行的说明公式：

```text
W = 基准正文一行可用宽度（同一坐标单位）
N = 实际可容纳正文行数
U = 标准显示容量单位
RAW_CAPACITY = floor(N × W / U)
SAFE_CAPACITY = floor(RAW_CAPACITY × 0.90)
```

最终算法还须扣除/计入客户端真实会画的 `「」` 等装饰和禁则换行边界，不能让两端括号把最后一行挤出。用户正文容量显示是否排除固定装饰由 profile 固定，运行和测量使用同一约定；不准一端计算括号另一端忽略。

### 7.3.3 自动折行仍然消耗空间

“作者不能手动换行”不等于“游戏只显示一条物理行”。自动 Wrap 必须保留。仅把字宽求和除以总宽度，仍不足以代表真实占用：在词边界或字符放不下时，上一行尾部空白已经不可用于后续正文。

因此容量计数依照标准自动折行结果，计入已结束行的整行预算及最后一行的已用宽度。例如对统一行宽W的结果：

```text
usedWidthBudget = (实际行数 - 1) × W + 最后一行实际已用宽度
usedCapacity = ceil(usedWidthBudget / U)
```

这是说明公式，不替代目标 FontRenderer 的换行行为；空文本、特殊格式符、Unicode 组合字符和禁则须由统一测量规则处理。一个不可拆字符的宽度本身超过行宽时，要报告不可正常容纳，不能仅以总容量未超限判“适合”。

UTF-16 code unit 不是用户字符；不能把代理对、组合符号切成两半。§颜色等已有支持的控制序列不占可见字宽，但影响字重/宽度的格式必须计入；不借本版增加富文本功能，也不把控制符切断到下一页。

### 7.3.4 余量与作者反馈

以理论容量160为例，SAFE才是144。此处只演示90%规则，**不是本版正式容量承诺**。

Studio 在每句正文右下方显示 `容量 X / MAX`。MAX只显示SAFE值；正常颜色、临近边界的温和提示、超过时红色及说明：

> 超过推荐显示容量；游戏可能分屏显示。建议拆成多句。

保持节点内与 Inspector 完全一致；Tooltip 简述“标准字体、150%字号、实际字宽、已含安全余量”。不要再同时放一个相互矛盾的“字数限制160”。

超过容量是**警告**：允许继续输入、保存和正式导出。只能由数据格式、安全字节限额等真正错误阻止导出。不要在 Schema、发布脚本或服务器载入器的另一处暗加容量硬拒绝。

90%只扣一次。不能在字体度量、正文矩形、显示单位和导出校验各扣10%，把实际容量压到用户不接受的程度。

不改 authored pages，不生成新 page_id，不在 Studio 或导出包中偷偷写入“台词1.5”，不改服务端游标。原句身份仍使用当前 transport/story/session/node/lineEpoch 的既有组合。

### 7.4.2 分页算法与完整性

进入新原句或显示条件失效时，先按**完整原文**计算自动折行和显示页，再只在当前显示页内逐字展示。不要每帧拿已露出的前缀重新排版，造成文字和右引号不断跳行。

保留原文字符偏移范围，使所有 Segment 的内容按顺序精确覆盖原文；不丢空格、不自动改标点、不在切分边界删除字。装饰引号属于显示，不写回原文。运行时使用当前玩家实际 FontRenderer、倍率和正文矩形。

显示页按真实可容纳行数与像素边界形成，不再把Studio90%推荐值当第二道强制分页阈值：处于安全余量内、实际仍能完整显示的文本不必额外翻页。

边界容量不足一行时先收缩辅助占位/调整对话区域以确保正文的最小可用空间；不能反复产生空页或无穷循环。自定义异常字形的精确美观不作保证，但错误路径不得裁掉源文本、破坏流程或抛未处理异常。

普通空句沿用现有合法性规则，不因为分页空集合造成卡死。超长合法句使用有界布局数据；不创建逐字符大型控件，不把分页数写入网络或世界存档。

### 7.4.3 单一推进入口

手动点击和自动计时共用一个 `AdvanceVisiblePage` 类操作（建议名称）：

| 当前状态 | 左键行为 | 网络/音频 |
|---|---|---|
| 当前显示页正在逐字显示 | 只补全**当前显示页** | 不发Continue，不调用音频advance |
| 当前显示页已完整，后面有Segment | 显示下一本地Segment，重新逐字/重新计时 | 不发Continue，不重播/停止语音 |
| 原句最后一屏已完整，未等待回执 | 按原有身份发一次Continue | 这时才走真正推进和原有音频advance |
| 正在等服务器 | 不重复提交 | 保持原页，不新建请求 |
| 是选择帧 | 只允许玩家按现有选项机制选择 | 不自动代选 |

`CanonicalSessionClientController.sendContinue()` 当前会调用 `MODEL.finishVisibleText()`，实际发送动作又会调用 `CanonicalSessionAudio.advance()`。[S07] 必须把本地页处理插在这条链之前，不能从渲染器绕过Controller，也不能每翻本地页停一次语音。

记录/自动按钮点击由控件消费，不能落入当前“任意左键继续”的处理。对话底层绘制不能吃到上层GUI点击。

### 7.4.4 字体、窗口变化与重同步

- 同一句重同步、主题切换或 `initGui()` 不把Segment索引、已读位置和等待状态重置为第一页。
- 采用原文绝对字符偏移作为重排锚点，不能只记“第2个Segment”：字号变化后分屏边界可能完全不同。
- 重排优先从当前未推进完的显示段起点继续；允许少量已经看过的文字再次呈现，不允许跳过尚未展示的文本。保持当前页已显示前缀，不自动发服务端动作。
- 换服务器/真实新原句/会话结束按既有生命周期清理；断线后恢复原句至少可从该原句第一页安全重播文字，不改变服务端剧情，不为本地分页增设持久化玩家进度。
- 前景对话与下层只读绘制使用相同状态；重新打开设置/记录后回原句，不重触发媒体。

## 7.5 自动播放（A11、T07）

按钮位于记录左侧，显示开启/关闭状态。不开启时完全保持手动操作；默认关闭，不强迫用户使用。

计时从当前 Segment **完整显示且对话处于可交互前台**后开始，经过玩家设定等待时长再执行同一个推进入口。页号变化或手动提前推进后，等待重新从零计算。

用单个受当前原句身份与Segment起始偏移约束的计时状态，不能每次点击/重绘都启动新的延时任务。相同包重同步不会重置成另一条计时器；等待服务端时锁住自动请求。

打开历史、设置、聊天、背包、Esc菜单、死亡或失去可交互前台时停止累计，不在背后推进。返回当前页时重新给足一轮等待，避免刚关设置立即跳走。遇选择暂停，不自动挑选，选项确认后依当前会话开关继续下一句。

语音仍非流程阻塞项；自动只等待文字显示与设定时长，不未经确认新增“必须等音频播完”。同一原句的后续本地Segment不重播配音；真正进入下一原句时才按原有行为处理下一条语音。

## 7.6 对话记录完整原句（T08）

当一条真正收到并开始显示的 LINE 原句进入展示时，一次性记录 `frame.getText()` 的完整内容。不是显示页文字，不是逐字前缀。

```text
屏幕先显示1A，玩家尚未点击1B：
历史已显示“原句1的完整文字”，只占一条记录。
```

“显示在同一行”按一条**逻辑记录**理解：长内容在历史窗口正常自动换行，不拆成多条、不强迫水平滚动。不要恢复后半句防泄露式追加。尚未真正到达的下一 authored page、其他分支或预加载包不写入历史。

按既有原句identity去重，重复帧/本地翻页/主题切换/下层重绘不得产生重复条目，也不得让已存在完整记录被短前缀覆盖。移除渲染循环中以shownText更新历史的依赖。[S08]

Choice“我选择”仍以服务端成功回执写入；不是点击按钮就认定结果，不能因为本次取消原句防泄露就撤掉这个事务确认。

同服务器/同存档250条、跨维度保留、跨服隔离、关闭客户端清空保持。清历史不能删除真实玩家选项、奖励收据、会话游标、任务完成记录。

## 7.7 Studio与客户端的一致性验证产物

至少保留以下测试样本与结果表：中文、英文宽窄字母、数字、全半角标点、空格、中英混合、标准支持Unicode、`「」`装饰、临界最后一行、特别长词、空正文；含非法手动换行的编辑拒绝样本。

每个样本同时记录：标准150%测量宽度、折行数、容量、SAFE比较、游戏实际页数与边界。保存一个实际结果规格，不只保存截图。预览工具与运行时即使分属C#/Java，也须共享生成的数值契约和测试向量，不能各自维护“差不多”的算法。

# 8. WP-C：任务追踪与奖励预览

## 8.1 追踪框紧凑化（A01）

当前 `panelWidth=min(200,max(100,width/3))` 的问题是把按屏幕得出的宽度当作常态。改为测量当前内容的自然宽度，经过最大宽度限制再自动折行；最终外框 = 实际内容边界 + 合理内边距。

高度仅包含本次真正显示的行、任务间隔和必要控件；没有溢出时不预留“另有N行”的底栏。短标题和一个短目标不能留下大块横向/纵向空白。

HUD 使用专门的半透明底板，不直接用窗口的0xEE/0xF0高不透明背景。默认右侧中部；计分板冲突保护保留，必要时避免越过屏幕。三主题实机确认文字对比度，不向P菜单增加Toast/Tracker布局或透明度设置。

全部ACTIVE目标继续完整纳入，不偷偷只取前三条，也不让已经完成的目标混成“还要去做”的目标。普通内容尽量全部直接展示；极端大量目标/极小窗口不能在有限屏幕承诺无限同时展示，应保留明确的溢出指示与任务菜单内完整访问，不静默丢弃。

只有任务快照/追踪选择/字号/逻辑尺寸变化时重排；不能每帧读取磁盘或请求服务器。追踪最多3个、新任务补空位不抢旧任务、完成后取消、持有数与真实提交进度分离等既定行为保留。

## 8.2 消除奖励中间态闪烁（A10）

`rewardStates=false` / `pending_rewards=true` 是发放流水线的中间态，不天然等于背包满。移除把普通pending直接拼成HUD目标或瞬间提示的路径。

保留服务端待发队列、原子事务、奖励收据、失败重试和结算约束。只是不把正常瞬态显示为“奖励发放阶段”。真正的持续发放异常应由准确原因给出任务面板状态或必要提示，不能一律说“请腾出背包空间”，也不能彻底掩盖奖励未到账。

不因删一条HUD文案删除Runtime待发字段，或提前强行结算任务以掩盖闪烁。

## 8.3 任务面板布局（A10）

把目标块改为有结构的测量对象，不继续把标题/进度/奖励全部压成无类型的字符串列表：

```text
消灭史莱姆                                  2 / 3
奖励：铁锭 ×10、经验 +100
```

长目标名称在左侧换行，计数在右侧固定保留区域，不能互相覆盖。收集/击杀显示进度；提交显示持有数及交互提交提示，不暗示已经完成部分扣款；角色交互和区域到达不加无意义0/1。无直接奖励不显示空“奖励：”行。

奖励预览主要放在I任务面板的目标下方，不把这堆详情再塞回紧凑HUD。任务长说明、区域坐标和已完成记录继续保留原职责。

## 8.4 直接连接奖励的只读投影

服务端在当前 Task 资源中，从目标完成逻辑输出查找**直接**连接到奖励逻辑输入的边，读取该奖励的有序entries并投影。多个直接奖励全部显示；重复连接/同节点重复引用按确定性规则去重，不因边表遍历重复承诺奖励。

不穿越AND/OR/NOT、公共逻辑或其他节点猜“最终可能奖励”；不给未激活目标提前发描述和奖励。目标面板展示是结构上的奖励预览，不改 `grantReward()` 或接线语义。

保持奖励条目的正负号与顺序。第一版不把“+10铁锭、-3铁锭”合并成+7，以免改变有序增减和容量约束的认知；负数明确“扣除铁锭 ×3”，经验标明获得/扣除。零量按统一规则隐藏或显示0，必须记录决定且不修改实际条目。

奖励仅允许个体Item资源的现有约束保持；不为本版补一个“从GroupID选哪种物品”的随机机制。

## 8.5 从实际指名物品取得名称

复用已有链路：

```text
奖励entry.item
→ ItemIdentitySavedData中的绑定
→ ItemStackDefinition
→ 受控的ItemStack显示数据
→ 客户端按玩家语言取得实际显示名
```

不扫描区块、实体或玩家背包，不要求作者再填“奖励描述”，不优先使用Studio自用资源别名。测试例：资源名“铜币”、ItemID绑定铁锭，面板显示“铁锭 ×10”。

服务端投影真实绑定定义，客户端用匹配的物品显示路径处理模组本地化和NBT自定义名。无绑定显示“无 ×10”；有英文而无当前语言翻译采用实际英文回退，不生成机器翻译；极端模组名称缺失或取名函数异常须提供可诊断占位，不能崩溃任务菜单。

网络仅传所需、有边界的显示数据，复用现有NBT/物品编解码；不得为图标/名字不加限制地广播完整物品目录或无关NBT。实际发奖状态仍以服务端为准，客户端名称不参与匹配。

绑定修订、任务快照或语言/资源刷新后失效缓存；重新指名后更新奖励名。该名称刷新不产生“新目标”Toast，不重置任务，不重新发奖。

已完成任务只读摘要不回退；不要把新的“当前可能奖励”展示伪装成历史上实际领取清单。没有历史发奖快照时不补写虚构账本。

# 9. WP-D：留声机外观、范围显示、试听与缓存

## 9.1 现有方块的正式外观（A12）

当前留声机已经是独立注册方块，缺的是正式美术，不是缺一个新的Block。保留现有注册名称、TileEntity、权限、红石和设备身份，不另注册一个并行“新版留声机”。

移除 `jukebox_side` 占位依赖；制作可识别的环境留声机外观及匹配物品栏图标。优先选择适合 Minecraft 1.7.10 的简单低面数造型和一致纹理，不为装饰引入庞大动画/渲染框架。最终具体造型由实机视觉稿确定，本文不把未制作美术描述成用户已批准成图。

验证世界放置、至少四方向观察、选中框/碰撞箱与模型、手持、物品栏和光照。保留不可被普通玩家拆除/修改等原有创作权限；不得把模型渲染代码加载到专用服务端。

## 9.2 范围显示脱离 GUI 生命周期（A13）

保持实际播放判定：

```text
playerDimension == deviceDimension
abs(floor(playerX) - deviceX) <= radius
abs(floor(playerY) - deviceY) <= radius
abs(floor(playerZ) - deviceZ) <= radius
```

边界框画在包含方块的外边界：`[x-r, x+r+1]`、`[y-r, y+r+1]`、`[z-r, z+r+1]`。半径16即每轴包含33个方块位置，现有预览与播放公式一致；不要未经测量把它改成球形或边长32来“看起来更像16”。

显示范围是一项**创作者本地可保存的可视化偏好**，不是服务器音乐开关。用稳定的服务器/单人存档上下文＋维度＋方块位置＋设备实例识别，避免换服或同位置新设备继承错误显示。

配置界面采用“显示范围”明确toggle；打开后，关GUI仍显示，重开读取同一状态；关闭后停止显示。保存在现有Config目录的适当本地配置中，不存进普通玩家任务数据，不向所有玩家广播粒子。

世界绘制不再要求 `currentScreen instanceof GuiGramophone`。只渲染当前世界中经授权的有效设备，按维度和存在性过滤。开多个显示范围时可以并存，范围重叠不做音乐仲裁。

GUI里正在编辑但尚未保存的半径可作临时预览；退出并放弃修改后，用设备已保存的真实半径继续画。显示开关的保存不应顺便保存音乐来源/半径草稿。

设备被移除、实例替换、权限失效时清理显示；维度切换暂时不画其他维度，回到原维度可按本地偏好恢复。范围渲染完整恢复GL状态，不破坏透明、深度、字体或其他模组世界绘制。

半径0、1、16、最大允许值，正负坐标和各个轴边界均做实测。至少用地面方块标记证明范围线框与实际播放进出点一致，而不是只从框内部拍一张看不见边缘的截图。

## 9.3 留声机 GUI 功能分区（A15）

保持现有业务，不增加一堆新开关。推荐结构：

```text
环境留声机

播放设置
  播放开关          红石控制
  播放范围          显示范围

音乐来源
  在线 / 本地
  单曲链接          或 本地文件及导入按钮

试听
  ▶ / 暂停          波形 + 可拖动进度 + 当前/总时长
  简短状态/错误

保存                删除音乐                关闭
```

卡片不是给每个字段单独围框，而是把功能模块分清。三主题下文本框、禁用状态、错误、多行状态都可读。几何和点击共用布局；缩小窗口时改成合理堆叠或内容滚动，不压线、不截关键操作。

删除单独“解析并准备试听”按钮。点击▶后，有有效缓存直接播；无缓存则异步准备，成功后自动试听。准备中按钮体现状态并防重复提交；重复点击可以取消正在准备，不排队启动多个试听。播放中同按钮暂停，之后从自身试听位置继续。

输入链接后未点击▶不自动联网；修改链接后旧结果不得覆盖新输入。保存在线配置可以复用已经规范化来源，不要求再次手动解析；对未规范化/无效输入给出准确错误，不承诺平台限制之外曲目可播。

切换在线/本地、取消、关闭窗口只停止编辑器自己的试听；不得暂停附近正式设备、不改服务器开关。导入仅创建草稿，不能上传。

## 9.4 试听缓存与资源引用（A15）

问题不是“全系统没有缓存”，而是 `GramophoneDraft` 的关闭与媒体文件销毁绑得太紧。修复使用已有文件生命周期与共享媒体能力，不把GUI保存成常驻后台窗口。

分离三个所有者：

| 所有者 | 负责什么 | 结束时做什么 |
|---|---|---|
| 编辑草稿 | 当前输入、选择的本地文件、未保存参数 | 放弃草稿，不提交服务器 |
| 试听播放实例 | 当前位置、暂停、当前解码器 | 停自己的声音并释放媒体租用 |
| 媒体缓存项 | 已校验的文件、波形/时长、规范化来源、最后使用时间 | 无租用且超期/超预算才删除 |

关闭GUI释放草稿与播放器，但缓存项可以继续存在。重开相同已保存来源，取得同一有效缓存并重建轻量试听UI，不重新下载/全曲解码。试听位置第一版不要求跨GUI保存，重新打开从0准备即可，正式设备的个人播放位置不受影响。

来源键：平台＋规范化歌曲ID，必要时含本地服务器/存档隔离；本地音频按内容指纹及授权上下文。临时CDN URL不能作为唯一长期身份。缓存合法曲目结果不包含用户账号/平台凭证。

沿用已有媒体文件pin/引用保护与容量预算，不另加无界缓存。初始实施默认可让无引用的试听条目保留一段短期空闲时间（例如30分钟）并受现有留声机缓存预算约束；具体值写入技术记录，不能把这个示例当成新增玩家设置。GUI缓存与设备缓存可共享资源句柄，但播放实例仍独立。

旧未保存、无人再用的本地草稿及时淘汰；同一文件多次试听或多台设备引用不复制多份。容量清理、关闭客户端后清理/下次启动回收残留继续存在；不能为了重开命中让100次导入的全部音频永久保留。

网络、解码、波形生成在有界worker完成；UI只接收仍对应当前generation的结果。关闭、换源、断线和异步错误之后正确取消/释放，不让晚到结果重新播放。正在播放、校验或传输的文件不能被GC。

缓存损坏/缺失/来源失效时重新准备并给出正确状态；有限重试，不每帧重发。网络失败不删除正在生效的已保存音乐配置。

## 9.5 保存与上传不回退

在线保存仍保存规范化来源/配置，不把试玩下载自动当成本地音乐上传。QQ/网易云的公开匿名范围、HTTPS校验、重定向和大小限制不放松。

本地仍为导入→试听→保存→明确确认上传→服务器完整校验→原子替换。关闭或取消不上传；成功前旧音乐继续可用；删除音乐释放该设备引用，不直接删掉其他设备仍在用的媒体。

不同GUI实例、设备revision、服务器/存档上下文不能共享错误上传结果；包/媒体指纹和pin机制不因GUI改版失效。

# 10. WP-E：组合、嵌套分组及 G 手势

## 10.1 定位与数据模型（G05、G06、G10）

这是 **Studio 编辑对象的组合**，不是增加 Runtime 节点类型。外观继续是半透明分组框，数据由扁平Frame升级为有显式层级的组合树。

实施模型建议：一个组有内部稳定标识、标题、可选现有样式，以及有序直接子对象；子对象明确区分 `NodeRef` / `GroupRef`。节点与组各有最多一个直接父组，图中允许多个根组及未分组节点。

内部group标识只服务编辑器，不进用户资源库，不叫NPCID/ItemID，不增加可被剧情引用的ID语义。只维护一个父子关系真值源；反向父索引若存在只能是派生缓存，不能两份独立可写归属表。

节点位置继续优先使用现有图坐标体系，避免因嵌套再引入一套影响连线的局部坐标。组的视觉bounds由直接成员及子组bounds计算；可缓存但不成为人工手动尺寸的独立真值。

禁止自包含、祖先入后代、重复成员、跨图成员、悬空引用。一次操作整体验证后提交，非法组合不作半套变更。一个组剩1个成员仍保留标题/结构；最后成员被移走后清理空壳组，递归清理因此变空的祖先，但不删除真实节点。

## 10.2 可见入口（G01）

在当前图工具栏的剪刀按钮**右侧紧邻**增加“组合”。保持现有控件高度、边距、文字/图标风格，不另开控制面板。

- 点击按钮与按一下G调用同一组合命令。
- 没有足够有效对象时置灰或无操作，不创建无意义空壳。
- 悬停短暂停留后显示：

```text
组合所选内容（G）
按住 G 拖动节点，可加入、移出或转移分组。
```

按钮是可发现的主入口，不要求用户先查快捷键表。右键只提供对当前对象有用的操作，不列出全图几百个组作为目标菜单。

不把旧C快捷键、Ctrl+P、Alt+P作为新的必需入口；本版分组发现和学习路径统一到按钮/G。剪刀原有行为保留。

## 10.3 选择与命中（G02、G04）

**选中一个节点不等于选中它的组；选中某组的所有节点也不等于显式选中了那个组。** 必须保留这两种选择的类型，否则“融入”与“嵌套”无法区别。

- 点节点非控件区：选择该具体节点；拖动、删除只作用于该选择集合。
- 点节点内输入框/按钮/资源选择：执行控件编辑，不被组抢走。
- 点组标题、边框或组内未被交互对象占据的空白：选择这个组整体。
- 嵌套组空白：选最内层被命中的组；外层仍有标题/内边距可选。
- 组后面的画布不遮挡节点、端口、连线交互；命中优先级为前景控件/节点/端口与连线交互区，然后最内层可见组，再画布。
- 组视觉重叠不改变成员；同级重叠时按明确显示Z序命中，只高亮一个实际目标，不用字典遍历顺序猜。
- 保留既有Ctrl多选语义用于节点与组混合选择；视觉上组边框选中与单节点选中必须明显区分。
- 从画布空白开始的框选继续可用，不被新组背景命中无故吃掉；框选的默认选择单位为节点，不把“框选到全体节点”自动提升为组。组整体通过点击组/标题加入选择，保证用户的两种操作可区分。

选中祖先组与其后代时，整体命令展开对象前先按**选择对象类型**去重；移动/删除/复制不能给同一个后代执行两次。但不能为省事把整个选择转换成节点集合并丢失组对象。

## 10.4 组合命令决策表（G03）

优先归一化重复选择及已选祖先覆盖的后代，随后执行下表。字母是例子，不是节点/组真实ID。

| 场景 | 选择内容 | 结果 |
|---|---|---|
| 新建 | 多个未分组节点a/b/c | 新建组A，包含这些节点 |
| 借成员定位目标 | 未分组D＋组A中的任意一个/多个节点 | D加入A；A未选中的成员保持，不新建一个替代A的组 |
| 指定目标转移 | 组B的节点甲＋显式组A | 只将甲从B移到A；B其他成员不动 |
| 融入 | B的全部节点（不是B对象）＋显式组A | 将这些节点移入A；B为空后消失 |
| 嵌套 | 显式组A＋显式组B | 新建外层组C，A/B作为子组保留 |
| 混合嵌套 | 显式组A＋显式组B＋未分组X | 新建C；A/B为子组，X为C直接节点 |
| 一个明确目标 | 显式组A＋若干具体节点 | A为目标，节点转入A；已在A中的节点不重复添加 |
| 无明确目标、多来源 | 未显式选组，所选节点来自多个不同组 | 仅将这些选中节点组成一个新组；未选中节点与原组保持，空原组清理 |
| 已同属一组、无新成员 | 未显式选组，所有选择已在同一组且无外部节点 | 无结构变化；不为重复G制造无穷嵌套 |
| 不足以组合 | 无选择、单个未分组节点、仅一个组 | 不创建新组；保留选择并给必要的轻提示 |

其中“多个来源无显式目标”与“已同组无新成员”是本文为避免歧义给出的**实施默认**，不把未选中成员随意吸入。一般决策为：两个及以上显式组→创建父组；一个显式组→目标容器；没有显式组→先检查唯一已有组的便捷加入例子，再走新建/无操作分支。

创建嵌套组时优先放在所选对象原父链的最近公共容器内，没有共同组则放图根；不能跨图。显式选中父组和它的子组，不创建循环：归一化为父组选中一次。所有变更保留节点图坐标与连线。

新组标题使用简洁默认名，可立即重命名；不得弹出一个包含全图组的目标列表。对已存在组的加入/融入不随意改其标题或内部身份。

## 10.5 整体移动、删除与取消组合（G04、G08）

### 移动

左键按住组空白/标题并超过正常拖动阈值，即拖动整个组和所有递归后代。不是只在标题上才可拖，也不是必须按住若干毫秒。点击而未拖只选择。

单个成员的普通拖动只改位置，不改变父组，即使它穿过别的组；自己的组随内容自动扩展。所有组移动按实际图坐标增量处理缩放，不因100%/50%视图使节点移动两倍或子组漂移。

连续拖动仅为一次Undo事务；Esc或失去捕获取消预览，恢复操作前成员位置/层级。相同节点被多个选择覆盖时只移动一次。

### 删除

- 选节点后Delete：删除该节点及按既有规则处理的关联边，不额外删除同组其他节点。
- 选组后Delete：删除该组、所有子组及其全部后代节点，复用现有删除确认/资源引用规则。
- 固定唯一节点、只读引用节点、Project图谱受限对象不能被组删除绕过。若现有规则禁止该集合删除，则原子拒绝/走既有确认，不偷偷只删一半。
- 完整组被删除是一次事务，Undo一次恢复原身份、层级、位置、边以及合法的资源操作。

### 取消组合

组右键必须有“取消组合”，与“删除”分开。取消组合只移除当前组壳：直接子对象原地提升到它的父组（根组则提升到图根），内部子组仍保留原结构。

例如取消C（含A、B），A和B仍存在；不递归解散A/B。取消组合不会删除业务节点、端口、连线或Runtime资源，也不会重新生成后代ID。

## 10.6 自动适配大小（G05）

组永远按直接子对象的实际边界＋固定留白＋标题空间计算，父组再按子组边界逐层计算。节点逐句折叠、正文编辑改变尺寸、Undo、资源更新后均刷新。

不提供手动Resize、不保留手动固定宽高与AutoFit同时生效的两种模式，也不需要“适应内容”按钮。标题保留可选区域；长标题不能让框无限横向扩大，使用合理省略/Tooltip或限定标题区布局。

既有折叠动画220ms/CubicEase表现保持。组的派生bounds可在动画时更新，但不能每帧写sidecar、创建Undo或删除重建所有连线/Frame控件。只对脏组及祖先重算；连线依现有端点几何更新。

## 10.7 单点G与G拖动的事件仲裁（G07）

不使用“长按300ms”等时间阈值，不在KeyDown一到就先组合再等待拖动。

```text
G KeyDown（图操作上下文、非重复）
→ 记录一次候选按键手势，不立即改图

未发生拖动，G KeyUp
→ 组合一次（等价按钮）

G保持期间已经发生真实节点拖动
→ 临时成员编辑预览
→ 本次按键标记已用于拖动
→ G KeyUp 不再补执行组合
```

允许先拖节点，再按G进入高级预览。松开G立即取消成员更改预览，回普通排版；后续鼠标释放只提交布局，不再偷偷改变归属。只要本次G参与过拖动，就不在释放时补一次组合。

Esc、窗口失焦、丢失鼠标捕获、弹出模态窗时取消未提交组操作，清理G状态。KeyRepeat不能反复组合；文字框/搜索框/标题重命名/IME内的g/G是文字，不触发命令。

与现有Ctrl多选、Shift插线、Alt剪刀互斥且不抢输入：只在节点拖动上下文且有效G手势时改成员，不对端口拖线、数值拖动、台词条目排序套用G。组合按钮保留当前图选择，不因自身抢焦点清空目标；但要先按既有规则提交正在编辑的草稿。

## 10.8 G拖动的目标判定与防追边（G07）

首版高级手势处理节点（可包含多选节点）；组自身的嵌套组合使用§10.4命令，不额外扩展一套未讨论的组拖放重父规则。

G是明确的意图修饰键，因此加入不要求巨大节点完整塞进小框。以当前鼠标图坐标落入的合法组为候选，组边框高亮并显示操作结果：

```text
加入「A」
从「B」移入「A」
移出「B」
```

普通重叠不改归属。按住G松开鼠标且候选合法，才把位置和成员变更作为一次事务提交；仍在原组则只重排；不在任何候选组时移至图根。离开子组但落入其父组的独占空白时，候选是父组，提示明确。

必须解决“自动框追着被拖节点变大，永远拖不出去”的问题：在节点拖动起始时保存相关组的预览边界；G模式中以该手势开始前的边界或等价稳定目标快照判定成员出入，不用被当前拖动撑大的框反过来判定自身成员。自动适配在最终提交后应用。

目标在整个高级拖动中稳定，鼠标路径上的其他无关节点不会被自动加入。嵌套命中最内层合法组；重叠同层按稳定Z序；只显示一个目标。松开G或取消预览后不留下半转移数据。

## 10.9 持久化、复制与搜索（G09–G10）

扩展现有编辑sidecar，不把组合写入Canonical节点Properties/Ports。保存层级、标题与必要编辑状态；自动bounds是可重建缓存，不能成为运行语义。

当前扁平 `GraphCommentFrame` 可做一次性读取转换：旧成员按节点子对象导入，保留组标题与实际节点位置，尺寸重新Fit。转换前保留原sidecar备份；如果旧结构有冲突/缺失，只处理编辑元数据并给诊断，不删除用户业务节点。禁止同时运行旧Frame与新Group两套交互。

复制/粘贴：

- 显式选组时复制完整组树及其节点；新粘贴组/节点/必要资源身份按既有复制规则生成，不碰原对象。
- 选节点则复制节点，不因为“刚好选全组”擅自复制组壳，保留用户刻意区分的两种选择。
- 组＋子孙混选先去重，不复制两份同一后代；范围内连线复制，范围外连线不克隆。
- 会话/任务资源深复制、单次资源去重、参数粘贴等原规则不变；组不是绕过固定唯一节点/只读Project限制的途径。
- Group操作本身不重建节点运行ID；Undo/Redo恢复原ID，不为撤销随机生成新ID。
- 搜索定位节点或具体page_id仍进入正确图；新的组标题查找、定位/适应视图应至少不被嵌套结构破坏。定位子组高亮其可见边界，不把组做成折叠代理节点。
- 用“只改组/布局”的前后导出对照证明，业务图语义、端口与运行结果没有变化；若导出本来含布局坐标，只比较其被允许的展示差异，不要求整个ZIP字节哈希必然相同。

现有删除/复制/多选规则的测试应升级，不可仅替换UI后删除所有旧测试来获得全绿。

# 11. 数据、协议、线程与性能边界

## 11.1 状态归属表（X01）

| 状态 | 唯一所有者 / 存储 | 明确禁止 |
|---|---|---|
| Story/Session/Task游标、Choice结果、奖励收据 | 原有服务端/世界持久化 | 用本地分页、自动开关、历史清理改写 |
| 作者一句台词及page_id/媒体配置 | 原有Studio资源与DGRS | 为溢出插入新作者页、擅自改语音分配 |
| 标准字体容量profile | Studio/客户端共享数值规格与测试向量 | 放进每个台词的资源参数、要求作者维护字符权重 |
| 容量提示和编辑草稿 | Studio编辑器状态 | 将超SAFE当作数据损坏、每个字符一次Undo |
| 显示分屏/逐字位置/自动倒计时 | 当前客户端原句展示状态 | 服务端另建分屏任务或持久化“1.5句” |
| 完整原句阅读历史 | 本地按服务器/存档隔离的有界内存 | 随维度切换清空、混服、进玩家NBT |
| 两类音量/等待时长/主题等偏好 | 现有Config本地设置 | 增加第三个隐藏有效音量、覆写原版分类设置 |
| 奖励名字/图标预览 | 服务端真实绑定的只读投影＋客户端本地化缓存 | 名称参与发奖匹配、扫描全世界、修改奖励包 |
| 组层级/标题/成员 | Studio图级sidecar | 进入运行图端口、通过几何重叠修改关系 |
| 组bounds | 从正式成员布局派生的缓存 | 同时存在人工大小与自动大小两个真值 |
| 留声机显示范围开关 | 创作者客户端持久偏好 | 绑GUI实例、当成全服广播或播放开关 |
| 试听草稿/播放器 | 当前编辑会话 | 关窗影响设备、未确认自动上传 |
| 留声机已校验媒体缓存 | 现有媒体存储能力＋有界租用/回收 | 无界map、没人引用也永不删除 |
| 留声机正式曲目/范围/红石 | 现有服务端设备配置 | 本地预览直接覆盖正式值 |

## 11.2 协议和数据变化

文本容量和分页原则上**不增加网络字段**。继续复用原句的transport/story/session/node/lineEpoch；客户端本地Segment不能出现在正常Continue/Choice中。

奖励预览可能需要扩展任务只读投影字段，以最小必要信息完成；检视编解码长度、字段缺失行为与服务端目标可见性。缺少预览字段只表示没有预览，不能导致任务状态丢失。测试时客户端和服务端使用同一版正式产物，不为旧预发行客户端再造平行协议。

组层级只升级编辑sidecar，不新增Canonical Runtime schema。旧扁平sidecar的有限读取转换在§10.9明确；不做全项目批量重写资源ID。文档中旧路径和源码注释可同步清理，但不得为了“删旧字样”误删仍有用途的调用。

偏好写入沿用现有安全保存方式，只改对应键；非法数值回退默认并记录，不能清空整个Config目录。窗口几何/字体偏好变化不能触发保存服务器进度。

## 11.3 必须删去或替换的旧路径

完成后检查正式调用链，确保不存在继续生效的：

- 正文的 `scrollLine / maximumScroll` 交互及滚轮提示；历史/任务/选项的滚动另行保留。
- 主题/字号的盲目循环点击路径。
- 以普通pending直接显示“背包满”的HUD/任务文案路径。
- DGR声源对原版Music/Players音量的乘数及第三个独立留声机玩家音量。
- `shownText` 在逐帧渲染中覆盖完整历史文本。
- 老Frame右下Resize、body不可命中、默认删除框保留节点与新组语义同时生效的路径。
- G KeyDown直接组合而G拖动又再次组合的双重执行。
- 试听缓存只由GUI拥有、关窗立即销毁可复用文件的唯一路径。
- 范围绘制以留声机GUI必须打开为唯一条件。

这是替换正式行为，不要求删除所有同名辅助字段或测试fixture。每个保留项说明用途，不能留下第二套能被用户误入的界面或Runtime。

## 11.4 线程与性能

文本测量、格式规范化、容量计算应为线性或接近线性；不要对每个前缀反复调用全句Wrap造成长文本平方增长。逐字显示只更新可见范围，不逐帧重新分全部页。C#实时计数可以合并一次输入事件内的通知，但不能等失焦才显示。

组操作的数据变更放在现有编辑线程与事务中；重排只更新受影响节点端点与祖先bounds。拖动过程中不得逐帧新建所有Frame控件、连线或保存磁盘。层级遍历有循环保护和合理实现边界，不因特别深的嵌套栈溢出。

奖励绑定解析和投影按snapshot/catalog revision缓存；客户端取名只在显示数据/语言变化时刷新。不得每帧打网络、读整份目录或遍历世界实体。

在线解析、下载、音频解码、波形生成与缓存回收使用已有有界异步IO。主线程不能因点击▶同步等待整首歌下载。后台结果按generation/上下文核对，取消后不产生僵尸音源。

测量实际帧时间/排版次数/内存和缓存文件数量，与基线对比；不凭“只有几行代码”宣称没有性能影响，也不要为微小收益引入新常驻后台平台。
