## 3. Canonical Identity Contract 纠偏记录

当前已经确认的正确约束：

- Studio 中 `Task Objective` 的 `kill_entity` / `interact_actor` 目标是 **DGR Actor / Actor Group identity**，不是 Minecraft/Forge 原生实体类型。
- 用户现有测试项目已经定义 `史莱姆 / Group_ID = slimes`；任务“消灭3只史莱姆”应匹配这个已有 Group ID。
- 不得创建新的 `NPC_ID = slime`，不得重编织或修改用户已完成的 Story / Task 来迎合测试。
- 正式 Vertical Slice 必须选择一个原生种类与目标名称不同的 Minecraft 实体，通过 Nominator 指名为已有 DGR Actor/Actor Group identity，再通过真实 Forge gameplay event 验证 Objective 推进。
- 未指名的同种原版实体不得推进该 DGR Objective。
- `minecraft:*` registry identity 即便保留为 Runtime compatibility signal，也不得成为 Studio Canonical Objective 的正常 authoring contract。

已知错误假设：

1. **NEED_ARCHITECTURE_REVIEW**：错误地把 `kill_entity` 的 DGR target 当成 Minecraft 原版实体种类，并用原生 `EntitySlime` 与“史莱姆”名称/类型巧合来证明 Objective 匹配。
2. **NEED_ARCHITECTURE_REVIEW**：在用户项目已经存在 `Group_ID = slimes` 的情况下，错误尝试创建新的 `NPC_ID = slime`。
3. **NEED_ARCHITECTURE_REVIEW**：曾把原生类型兼容信号与 Canonical authoring identity 混为同一个验收契约。
4. **NEED_ARCHITECTURE_REVIEW**：现有自动化探针与原生史莱姆现场不能证明“异种原生实体经 Nominator 指名后推进、未指名同种实体不推进”的 Identity Gate。
