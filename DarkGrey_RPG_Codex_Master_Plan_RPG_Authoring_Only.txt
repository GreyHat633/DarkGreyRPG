======================================================================
一、项目重新定位
======================================================================

DarkGrey_RPG 当前阶段只做一件事：

“给 Minecraft 1.7.10 提供一个现代化、可长期使用的 RPG 任务 / 对话 / 剧情制作工具。”

当前明确不做：

- 自研 Native NPC 系统
- 自研复杂 NPC AI
- Boss 战框架
- Boss 技能系统
- 战斗演出编辑器
- 自定义怪物系统
- 自研模型 / 动画系统
- 用 DarkGrey_RPG 取代 CustomNPC+ 的 NPC 本体能力

当前直接使用 CustomNPC+ 作为 NPC 实体来源。

DarkGrey_RPG 的职责是：

1. 管理 RPG Actor 身份
2. 管理 Dialogue
3. 管理 Quest
4. 管理 Story / Interaction
5. 管理玩家 RPG 状态
6. 提供 Godot 式外部 Studio
7. 提供 Minecraft 内的运行时、测试与世界选择能力
8. 与 CustomNPC+ NPC 绑定
9. 完全绕开 CustomNPC+ 自带的 Quest / Dialogue 编辑逻辑

因此当前架构简化为：

DarkGrey_RPG Studio
        │
        ▼
DarkGrey_RPG Runtime
        │
        ├─ Actor Reference
        ├─ Dialogue
        ├─ Quest
        ├─ Story
        ├─ Variables
        └─ Debug/Test
        │
        ▼
CustomNPC+ NPC

CustomNPC+ 负责：
- NPC 实体
- 外观
- 模型
- AI
- 战斗属性
- 移动
- 动画
- 其它 NPC 本体能力

DarkGrey_RPG 负责：
- “这个 NPC 在 RPG 系统中是谁”
- “玩家和他交互时发生什么”
- “他说什么”
- “什么任务与剧情正在运行”

======================================================================
二、最重要的设计原则
======================================================================

1. 不复制 CNPC 的数据组织方式。

禁止：

NPC
└─ Dialogue
   └─ Quest

必须：

Actor
Dialogue
Quest
Story

四者是平级资源。

2. Actor 不是 NPC 本体。

Actor 只是 RPG 世界中的“角色身份”。

例如：

Actor:
tavern_owner

可以绑定到一个 CustomNPC+ NPC。

ActorDefinition 不负责：
- 模型
- AI
- 战斗
- 血量

这些继续由 CNPC+ 管理。

3. Dialogue 不拥有 Quest。

Dialogue 只负责：
- 说话
- 选择
- 对话分支
- 返回出口 Result

例如：

dialogue_exit = accept
dialogue_exit = refuse

但它本身不能：

StartQuest("xxx")

4. Quest 不拥有 NPC。

Quest 只描述：
- 任务目标
- 任务进度
- 完成条件
- 玩家任务状态

它不应该知道“谁发布了这个任务”。

5. Story 是资源编排层。

只有 Story 负责把：

Actor
Dialogue
Quest
Trigger
Condition
Action

连接起来。

6. Studio 是主要作者工具。

Minecraft 不是主要编辑器。

Minecraft 的作用：
- 世界视口
- NPC 选择
- 坐标 / 区域选择
- 测试窗口
- 实际运行环境

7. UI 操作逻辑尽量接近 Godot / Blender。

主要结构：

Project Tree
Workspace
Inspector
Output
Problems
Debugger
Project / Live
Play / Stop

1.3 Actor Reference
----------------------------------------------------------------------

ActorDefinition 非常轻量。

例如：

{
  "schema_version": 1,
  "id": "tavern_owner",
  "display_name": "酒馆老板"
}

它描述的是：

“剧情角色酒馆老板”

不是：

“NPC 实体模板”。

游戏中的某个 CNPC NPC 可以绑定：

darkgrey_rpg.actor_id = tavern_owner

一个 Actor 可以允许：
- 单实例绑定
- 多实例绑定（以后）
- 动态 Actor（以后）

第一阶段只做单 NPC 绑定即可。

4.3 酒馆老板任务正确制作方式
----------------------------------------------------------------------

Actor：

tavern_owner

Dialogue：

tavern_offer
tavern_complete

Quest：

kill_10_slimes

Story：

tavern_slime_request

Graph：

[InteractActor: tavern_owner]
        ↓
[QuestState: NOT_STARTED]
        ↓
[PlayDialogue: tavern_offer]
        ↓ accept
[StartQuest: kill_10_slimes]

另一个流：

[QuestCompleted: kill_10_slimes]
        ↓
[InteractActor: tavern_owner]
        ↓
[PlayDialogue: tavern_complete]
        ↓
[GiveReward]
        ↓
[End]

关键：

任务没有塞进对话。

对话没有塞进 NPC。

NPC 不知道任务存在。
