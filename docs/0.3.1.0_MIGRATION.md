# DarkGrey_RPG 0.3.1.0 Migration

## Back up first

Back up the Studio project, world, DGR configuration, and installed Story
Package directory before first production use. Test migration on a copy and
keep the previous 0.3.0.0 JAR/Studio artifact available for rollback.

## Studio project migration

Legacy 2.1.3 resources continue through the existing explicit migration
transaction:

1. Open the project in Studio.
2. Use the canonical migration preview.
3. Resolve every reported unsupported or ambiguous shape.
4. Confirm Apply only after reviewing the proposed file set.
5. Verify the generated backup and migration log before continuing authoring.

The transaction writes canonical resources beside legacy files, creates a full
backup, and rolls back on failure. It never silently overwrites or deletes the
legacy source files.

## 0.3.0.0 to 0.3.1.0 graph changes

- Chinese UI terminology changes from 剧情 to 故事; JSON `Story` identifiers
  do not change for that reason.
- Actor resources become `individual` (one `npc_id`) or `collective`
  (one `group_id`). Combat/appearance/AI fields do not belong in Actor
  resources.
- Item resources become `individual` (exact `item_id`) or `collective`
  (`group_id`).
- EnterStory is not a supported new-authoring node. Recreate the relationship
  with Story logic output/input ports and a Project Story Graph connection.
- Story Start owns explicit trigger definitions with stable output
  `port_id` values.
- Judgment/condition-trigger shapes migrate to the unified Condition contract.
- Task Activate and all internal flow nodes are removed. Objectives are active
  by default or are gated by explicit logic inputs.
- Every Task must have one Settlement node. Move terminal outcomes to its
  ordered, named, stable result ports. Intermediate facts belong on Task logic
  outputs.
- Give Item uses `item_id` and `amount`; old `item`/metadata authoring is
  not the 0.3.1.0 canonical schema.

Unsupported destructive conversions must produce a migration error/report.
Do not hand-edit stable `port_id` values after other resources reference them.

## World/runtime migration

0.3.1.0 creates separate SavedData for player RPG state, NPC identity,
Nominator selections/type rules, and Item identity. New unique NPC IDs are
external and cannot be copied with entity NBT.

The old `darkgrey_rpg.actor_id` CNPC Stored Data value is read only as a
compatibility fallback when no external DGR identity exists. Rebind important
NPCs with the Nominator to move them onto the external registry.

Normal `/dgr reload` replaces only validated definitions and does not clear
player state or reward receipts. If a new package is structurally incompatible
with active instances, keep the old package installed, restore the backup, and
review the server error instead of deleting SavedData.

## Story Package deployment

Export each Story into its own package directory. Install only on the server or
Integrated Server host under the configured Story Package directory. Clients
must not be treated as an authoritative package source.

For rollback:

1. stop authoring changes;
2. restore the last known-good package directory;
3. run `/dgr reload`;
4. verify that the old definitions were accepted and existing player state is
   still present.

## CNPC compatibility

Cloning a CNPC does not clone an external unique NPC ID. Groups may be inherited
where the chosen template/compatibility path explicitly carries them.

If a CNPC resurrection creates a new UUID and no stable old-to-new key exists,
0.3.1.0 does not guess. Use explicit Nominator transfer and record the operation
in production acceptance notes.
