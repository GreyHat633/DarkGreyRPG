# Studio 2.1.2 Node and Port Contract

`StoryNodeDefinitionRegistry` is the Studio source of truth for canonical node
types, aliases, Chinese display names, categories, property metadata, resource
reference kinds, and output strategy. Runtime JSON names remain compatible;
localized labels are editor presentation only.

## Output strategies

| Strategy | Contract |
| --- | --- |
| Single next | One `next` output. |
| Boolean | Exactly `true` and `false`. |
| Dialogue exits | Named outputs parsed from `exit_names`, deduplicated in stable order. |
| Sequence | Numeric outputs in numeric order, with connected-step deletion protection. |
| Terminal | No outputs. |
| Legacy preserved | Registry outputs plus compatible outputs already present in loaded connections. |

An output name is the persistent identity used by connections. Property UI may
change labels, but it must not silently rename or discard connected output
identities. The invariant “one edge per `from + output`” is enforced by the
connection ViewModel and validator.

## Property presentation

Required and frequently edited properties appear in the core section.
Compatibility or less common fields remain in the advanced section. Unknown
properties are preserved and remain editable instead of being dropped.
Resource references use a searchable selector backed by project resources;
free text remains available for compatibility and missing-reference repair.

Collapsing parameters does not collapse ports. The header continues to expose
the parameter count and summary, while Branch, Dialogue Exit, Sequence, and
terminal port semantics remain visible.

## Add menu

The add-node menu is generated from the registry categories: triggers,
conditions, dialogue, quests, actions/rewards, flow control, and stories. A
canonical definition must be unique, have a stable Runtime mapping, and have a
complete localized label before it can enter this menu.
