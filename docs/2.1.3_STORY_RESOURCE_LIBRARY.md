# DarkGrey RPG Studio 2.1.3 Story Resource Library

The Story workspace presents one compact, virtualized library per resource
kind (Actor, Dialogue, and Quest). Owned and Referenced memberships are mixed in
the same list and use the same visual contract. There is no separate “本剧情”
and “引用” list.

Each card shows the display name and resource ID. A resolved reference has the
shared vector link icon; a missing reference has a distinct warning icon. The
tooltip identifies the Home Story/source. Owned resources have no permanent
“来自” or “本剧情” text. Selection is a restrained background with a left
accent indicator, while hover and keyboard focus remain visible without
changing card size.

The list uses a single ScrollViewer with content scrolling, recycling
virtualization, a real draggable scrollbar, wheel/Page Up/Page Down, and
Home/End navigation. The Story library width is shared by the three pages,
clamped to 220–380 DIPs, defaults to 280 DIPs, and persists in Studio settings.
The command bar keeps search flexible and places Create, Duplicate (Dialogue
and Quest), and Reference actions in a consistent location. At the supported
1100×700 minimum logical window, controls remain usable; larger windows use
the available horizontal space rather than leaving a fixed narrow search
column.

Project Home is separate from the Story workspace. It opens with a searchable
Story list and a derived, read-only Project Story Graph. When at least one
Story exists, the first visible Story is selected by default and its Overview
is shown. Search with no matches has a distinct empty state and does not mean
the project has no Stories. Returning from a Story workspace preserves the
selected Story. The Graph remains editor-only and never becomes Runtime logic.

## Automation and acceptance

Stable UI Automation names cover the Project Home list/Overview, the three
Story command bars and libraries, Create/Copy/Reference commands, Draft empty
states, Dialogue named End, Quest empty state/completion modes, and the common
link/missing icons. The Release UI script checks real-process visibility and
navigation against a copied `.tooling` project; it does not perform the
resource-creation, duplicate, or reference mutations. Manual acceptance is
still required for those workflows, 100%/150% DPI, visual scrollbar dragging at
alternate scales, and interactive Minecraft client observation; these are not
inferred from Core tests or an isolated WPF process.
