# Studio 2.1 M5 — Dialogue + Quest Editor

## Scope

M5 replaces the Story workspace Dialogue and Quest placeholders with real WPF
editors. Both resources remain project-level identities organized by Story
membership. Actor, Dialogue, Quest, and Story ownership are not nested into one
another.

## Dialogue

The editor supports Line, Choice, and End nodes. An End node's `result` is the
named exit consumed later by Story Flow. Legacy Jump nodes can be loaded,
edited, and preserved, but are not offered as a new-node action. Dialogue does
not contain Quest actions.

The editor provides resource metadata, node CRUD and ordering, validation,
dirty state, save, and undo/redo. Speaker IDs are validated against project
Actors. A blank draft begins with a valid End node so it can be created before
the author adds a Line.

## Quest

The editor supports KillEntity, CollectItem, and InteractActor objectives.
Legacy ReachLocation objectives are preserved for Runtime compatibility. Quest
does not contain an issuer Actor or Dialogue ownership fields.

The editor provides resource metadata, objective CRUD and ordering, objective
group preservation, validation, dirty state, save, and undo/redo.

## Resource lifecycle

Dialogue and Quest use the same lifecycle semantics introduced for Actors:

- Create makes a new resource owned by the current Story.
- ImportAsNew copies content into a new independent ID.
- Reference adds the same project resource to another Story.
- RemoveReference removes only Story membership and preserves the file.
- Delete is blocked while any Story still owns or references the resource.

## Runtime compatibility

Studio writes schema version 2 with `display_name` and `home_story_id`. The Java
Runtime accepts Dialogue and Quest schema versions 1 and 2, ignores the two
editor-only identity fields after validating them, and keeps its strict unknown
field guards.
