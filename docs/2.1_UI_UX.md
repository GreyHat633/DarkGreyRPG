# Studio 2.1 UI and Interaction (2.1.3)

## Shell

Studio uses the built-in .NET WPF Fluent theme with dynamic system brushes.
The shell has a native menu, vector-icon navigation rail, resizable resource
browser, central workspace, status bar, and resizable/collapsible Bottom Dock.
There are no A/D/Q/S icon placeholders and no decorative New/Open hero buttons;
project creation and opening live in the File menu. The last project, theme,
recent project history, safe window size, browser width, and Bottom Dock height
persist independently from RPG project data. `文件 > 最近项目` lists only
known project directories that still contain `project.json`; selecting one
switches the whole workspace. `项目文件夹` opens the current project directory
in Explorer.

Programmatically created context menus use the same explicit Fluent base
styles across the Story list, Story Flow, and Project Graph. Their popups use
rounded theme-aware surfaces, Fluent icons, consistent 36-DIP item targets,
explicit separators, and a restrained danger color for destructive actions.

## Story-first workflow

Project is the outer workspace and Story is a resource inside that project.
Creating a project therefore leaves `stories/` empty. Users create the first
Story explicitly from the Project menu, the Project Home button or empty state,
or the Story-list context menu. `uncategorized` is migration support for real
legacy orphan resources, not a permanent visible placeholder.

The Project home opens on a searchable Story list and the derived Story Graph.
Selecting a Story shows its full Overview on Project Home: description,
resource ownership, and Flow node count. Opening a Story provides four editing
routes: Actors, Dialogues, Quests, and Flow. Create, import-as-new, reference,
inspect references, remove reference, and protected deletion use the same
commands and validation as the Core layer.

## Node canvases

Story Flow follows Godot AnimationTree/Visual Shader and Blender node-editor
interaction: nodes are freely draggable, ports are explicitly connected, the
canvas pans and zooms, rectangle and modifier selection are supported, and
copy/paste/delete/undo/redo operate on the graph. Named Dialogue exits become
ports rather than hidden string branches.

The Project Graph is also freely arranged, but its edges are read-only and
derived. Search, filters, auto layout, missing-target/isolated diagnostics, and
direct navigation to a Story's Flow are available.

## Accessibility and responsive behavior

Important editors, lists, graph canvases, ports, resources, and commands have
stable UI Automation names. Node controls expose accessible peers. Hover and
selected states use Fluent dynamic brushes without changing control size.
Text uses wrapping or trimming where appropriate.

Real WPF automation at a 1700x980 logical window verified critical controls were
visible and inside the window, the relocated Project Home Overview and all four
editing routes were navigable, and the Bottom Dock could resize from 120 to
about 220 DIPs, collapse, expand, and restore after restart. Evidence is in
`.tooling/2.1-acceptance/screenshots/08-...` through `12-...` and
`.tooling/2.1.2-acceptance/screenshots/00-...`.

## 2.1.3 resource creation and library contract

The 2.1.3 Story pages use one compact library for each of Actor, Dialogue, and
Quest. Owned and Referenced memberships are mixed in that list; a shared vector
link icon identifies a resolved reference, a separate warning icon identifies a
missing resource, and the tooltip supplies the Home Story. Cards remain
keyboard accessible, virtualized, and genuinely scrollable. The shared library
width is resizable within 220–380 DIPs and persists independently of Runtime
data.

Create and Duplicate produce in-memory Drafts. No JSON or Owned membership is
written before the first valid Save; Discard removes the Draft without touching
formal resources. Reference reuses the same project resource and never changes
its Home Story. New Dialogue presents an End named `complete` and can add its
first line; New Quest starts with no objective and no fake actor, then exposes
ALL/ANY/SEQUENCE completion modes. Project Home defaults to the first Story and
distinguishes “no project Stories” from “no search matches”.

Core/WPF tests and Release UI Automation are separate evidence layers. The
accepted 119-DPI Release run proved the exact resource-list physical scrollbar
drag (`ScrollPattern 0 -> 100`). Manual 100%/150% DPI comparison and Minecraft
client observation remain required; neither static tests nor an isolated WPF
window proves them.
