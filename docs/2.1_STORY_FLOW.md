# Studio 2.1 M6 — Story Flow Editor

## Scope

M6 replaces the Flow placeholder with a free-form WPF node canvas. It is a
Story-owned graph editor, visually and behaviorally aligned with Godot
AnimationTree/Visual Shader and Blender node editors rather than a list editor.
Dialogue, Quest, and Story Flow remain separate authoring responsibilities.

## Graph model

The authoring surface supports StoryStart, ActorInteract, PlayDialogue,
StartQuest, WaitQuestComplete, DialogueExitBranch, EnterStory, EndStory, and
End. Node positions and directed port connections are stored in the Story JSON.
DialogueExitBranch creates ports from its comma-separated named exits;
EnterStory targets another project Story.

Legacy Runtime nodes are accepted and preserved with their original persisted
type. Opening and saving an older graph therefore does not rewrite unsupported
authoring nodes into End nodes. New nodes use the 2.1 snake_case persisted
types.

## Interaction

- Drag one node or a Ctrl/Shift multi-selection to arrange the canvas.
- Drag an empty rectangle to box-select.
- Click an output port and then a target input port to connect them.
- Click a connection and press Delete to remove it.
- Right-drag pans; mouse wheel and toolbar buttons zoom.
- Ctrl+C/V copies and pastes nodes and their internal edges.
- Ctrl+Z/Y undo and redo graph edits.
- Editing a node ID updates its incident connections atomically.
- Resource pickers validate Actor, Dialogue, Quest, and target Story references.

## Persistence and validation

`StoryDocument` is the mutable, UI-independent editing boundary. The WPF view
model commits each edit into it, records snapshots for history, and saves via
`StoryRepository`'s atomic write path. Validation covers unique IDs, valid
entry and connection endpoints, one edge per output, finite positions,
required properties, and project-level resource existence.
