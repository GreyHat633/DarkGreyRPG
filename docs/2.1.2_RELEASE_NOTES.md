# DarkGrey RPG Studio 2.1.2 Release Notes

## Highlights

- Connect, reconnect, and disconnect Flow edges from either endpoint with
  atomic Undo/Redo and reliable pointer cancellation.
- Node selection, movement, connection edits, and Undo retain existing node
  controls instead of rebuilding the whole canvas, eliminating the parameter
  panel flicker seen during ordinary graph interaction.
- Grabbing an occupied port now moves that exact endpoint: the opposite end of
  the existing wire remains visibly attached throughout the drag.
- Central node definitions provide complete localized menus, stable port
  contracts, resource-aware property editors, and compatibility preservation.
- Problems navigate to an exact node field. Invalid Flow drafts are isolated in
  editor Recovery without changing Runtime Story JSON.
- Project Graph aggregates parallel transitions, renders arrows and self-loops,
  explains branch sources, lays out cycles safely, and navigates missing targets
  back to their source EnterStory.
- Project Home now has one Story navigation list on the left. Selecting a Story
  shows the complete former workspace overview on the right: description,
  resource ownership, and Flow node count.
- Project and Story creation are now separated explicitly. A newly created
  project contains no implicit `uncategorized` Story; `新建剧情` is available
  from the Project menu, Project Home button and empty state, and the Story-list
  context menu. Legacy migration creates `uncategorized` only when orphaned
  legacy resources genuinely need a home Story.
- Project Home exposes its secondary New Story action as a compact vector `+`
  command in the pane header. It no longer interrupts the list/graph/search
  rhythm with a second accent-text button.
- The File menu now exposes a bounded, persisted `最近项目` submenu containing
  only project directories that still have `project.json`. Selecting an entry
  switches projects directly, and `打开项目目录` is now named `项目文件夹`.
- The entered Story workspace now contains only the four actual editing routes:
  Actors, Dialogues, Quests, and Flow. Its duplicate Overview route was removed.
- Right-click a Story to access `打开剧情` and `删除剧情` directly. Deletion
  still requires an explicit warning confirmation. `uncategorized` is no
  longer permanently reserved. Its unshared owned resources are shown in the
  confirmation and deleted with it; external Story references and incoming
  EnterStory transitions still block unsafe deletion.
- Opening a project now upgrades legacy Dialogue and Quest resources alongside
  Actors and repairs Story membership from authoritative `home_story_id` data,
  so Overview, Story editors, deletion checks, and persisted files agree.
- Story, Story Flow, and Project Graph context menus now share the WPF Fluent
  menu template, with rounded popups, Fluent icons, 36-DIP targets, explicit
  separators, theme-aware colors, and a distinct destructive-action style.

## Upgrade from 2.1.1

2.1.1 projects open directly. Studio does not rewrite a Story merely because it
was opened. A Story changes only after a valid explicit save. Existing
PlayDialogue named outputs and unknown compatibility properties are retained.

The editor may create or update these editor-only files:

- `resources/editor/story-graph-layout.json`
- `resources/editor/recovery/<story-id>.json`

Runtime project loading ignores the Recovery directory. Back up a project before
large authoring sessions as usual; do not copy Recovery files into a Runtime
resource manifest.

## Known limitations

- The EXE is not Authenticode-signed.
- The recorded 2.1.2 real-window run used DPI 119, approximately Windows 125%
  scaling. Separate 100% and 150% screenshots still require those display
  environments.
- No interactive Minecraft client/player click-through of both dialogue branch
  choices was recorded for this build. Runtime behavior is covered by the data
  layer and deterministic probes, not claimed as client-visual acceptance.
- Project Story Graph remains deliberately logic-read-only.
