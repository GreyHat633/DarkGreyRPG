# DarkGrey_RPG 0.3.1.0_开发版 Release Notes

> This is a development preview, not the final 0.3.1.0 release. Automated
> compilation and focused integration checks pass, while the live gameplay
> acceptance items listed in `docs/0.3.1.0_ACCEPTANCE.md` remain unfinished.

0.3.1.0 brings the 0.3.0.0 canonical authoring model into a server-owned
Minecraft workflow.

## Highlights

- Export a selected Studio Story as a complete, deterministic Story Package.
- Install packages on a dedicated or Integrated Server and apply valid changes
  online with `/dgr reload`.
- Bind real living entities to unique NPC IDs and multiple Actor Groups without
  placing the unique identity in copyable entity NBT.
- Bind exact Item IDs and exact/fuzzy Item Groups from real inventory stacks.
- Use the multi-template Copier and Survival/Creative Storage Box while keeping
  unique identity rules intact.
- Wire stable logic outputs and inputs across Stories in Project Story Graph.
- Author Story/Session logic boundaries, Session Narration, unified Condition,
  pure-logic Tasks, gated Objectives, and one prioritized Settlement.
- Award exact DGR Item IDs through a server-side, idempotent `give_item`
  action.
- Run without CustomNPC+; when installed, CNPC entities can host DGR identities
  through an optional reflection-safe adapter.

## Compatibility

Legacy 2.1.3 migration remains explicit, previewed, backed up, and rollback
capable. Existing 0.3.0.0 player state is not cleared by normal package reload.
Removed or ambiguous graph shapes fail with migration/validation diagnostics
instead of silently losing nodes or ports.

Unique identities previously stored only in the legacy CNPC
`darkgrey_rpg.actor_id` field remain readable as fallback, but rebinding with
the Nominator is recommended.

## Known boundary

The inspected CustomNPC+ 1.11.1 fixed-v1 surface does not expose a proven stable
old-to-new identity key for every resurrection implementation. Automatic
unique-ID migration to an unrelated new UUID is therefore not claimed; use the
Nominator's explicit transfer operation.

See `docs/0.3.1.0_MIGRATION.md` and
`docs/0.3.1.0_ACCEPTANCE.md` before production deployment.
