# DarkGrey RPG Studio 2.1.3 Resource Creation Model

Studio 2.1.3 keeps Actor, Dialogue, and Quest as project-level resources. A
resource is stored at `actors/<id>.json`, `dialogues/<id>.json`, or
`quests/<id>.json`; a Story stores only its `owned_resources` and
`referenced_resources` membership. The Java Runtime remains version 0.5.0.

## Three explicit operations

| Operation | Resource identity | Current Story membership | Original resource |
| --- | --- | --- | --- |
| Create | new ID and new data | Owned after first successful Save | unchanged |
| Duplicate | new ID and copied data | Owned after first successful Save | independent after Save |
| Reference | same project ID | Referenced immediately | shared; its Home Story does not move |

Create and Duplicate open an in-memory Draft. Drafts are shown in the current
resource library but are not in the persisted registry, do not write a JSON
file, and do not change Story membership. Closing or switching away prompts for
Save, Discard, or Cancel. Discard removes only the Draft from the open-document
set; it never deletes a persisted resource.

## Draft and first-save transaction

The Draft carries `IsNewDraft`, `DraftOwnerStoryId`, `SourceTemplateId`, and
`HasEverBeenSaved` state. Dialogue starts with an `end` node and named result
`complete`; its first line action inserts `line_1` and routes it to `end`.
Quest starts with no objectives, no groups, and no fake `actor` placeholder.
The first objective is added explicitly, and completion mode is then selected
from ALL, ANY, or SEQUENCE.

First Save validates the Draft, writes the resource, updates the owning Story
membership, and reopens the saved document. If membership or the second write
fails, the original Story bytes are restored, a newly-created resource is
removed when possible, and the Draft remains available for repair and retry.
The UI reports the exception through Output/Problems/Toast and the global WPF
boundary logs it; a failed create must not terminate the application.

## Home Story and references

Each project resource has one Home Story (the owner). Referencing it from a
different Story adds only Referenced membership. The unified library uses one
list for owned and referenced entries: owned entries have no ownership label,
resolved references show the common link icon, and missing entries show a
separate warning icon. The reference tooltip identifies the Home Story. A
reference operation cannot rewrite the source resource's Home Story.

## Evidence boundary

Core and WPF ViewModel tests prove data invariants and command behavior without
launching a desktop process. `studio/qa/2.1.3-resource-creation-ui-acceptance.ps1`
is the Release WPF/UI Automation layer: it uses a copied project below
`.tooling`, checks persisted JSON and membership invariants, captures
screenshots, and keeps an atomic result file for each run. The accepted live
workflow proves Dialogue and Quest Draft no-file/no-membership state, first
Save, restart persistence, Duplicate independence, Reference shared identity
and Home Story preservation, and a physical resource-library scrollbar drag.
The live run reports current-host DPI visibility (119 DPI on the accepted
host). Manual 100%/150% visual comparison, Minecraft client click-through,
packaging, and Runtime probes remain separate evidence layers.
