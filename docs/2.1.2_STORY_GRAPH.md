# Studio 2.1.2 Project Story Graph

The Project Story Graph is a derived, logic-read-only view. Its nodes come from
Stories and its edges come from `enter_story` nodes. Moving nodes, panning,
zooming, filtering, searching, auto-layout, and opening context menus may update
editor layout state, but must never edit Story nodes, connections, or JSON.

## Edge model and rendering

Transitions sharing the same source and target are aggregated into one edge.
The edge retains every source EnterStory node, its target, and incoming branch
outputs; the tooltip explains these branch reasons and the canvas shows `xN`
for an aggregate.

Each edge renders as:

1. a wide transparent hit-test shape with an automation peer and Invoke action;
2. a narrow visible Bézier stroke;
3. an arrow polygon at the target end;
4. an optional aggregate count label.

Self-transitions use an explicit loop above and to the right of their Story
node. They do not collapse into a zero-length curve. Normal arrows end on the
target node boundary.

## Layout and cycles

Auto-layout condenses strongly connected components before ordering the graph.
Cycles and self-loops therefore terminate in finite time and receive finite
coordinates. Layout persistence is editor-only in
`resources/editor/story-graph-layout.json`.

## Problems navigation

A missing target produces a source-scoped Problem containing Story ID,
EnterStory node ID, and `target_story_id`. Double-clicking it opens the source
Flow, centers the EnterStory node, expands its properties, and focuses the
target resource selector. Other graph diagnostics return to the graph and
focus their Story node.

The edge menu can open source/target Story overviews or one of the aggregated
source EnterStory nodes. None of these operations has a Story save path.
