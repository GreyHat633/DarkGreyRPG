# DarkGrey_RPG 0.3.1.0 Architecture

## Product boundary

0.3.1.0 is the Minecraft deployment/runtime layer for the canonical 0.3.0.0
authoring model. Story Flow remains the only side-effecting orchestration
language. Session and Task remain scoped graph resources, while Project Story
Graph exposes only stable cross-Story logic interfaces.

DarkGrey_RPG owns its runtime, identities, Story Packages, dialogue UI, Journal,
and player progress. CustomNPC+ is optional and is reached only through a
reflection-safe compatibility adapter.

## Authority and persistence

- Story Package installation and reload are server-owned.
- Story, Session, Task, Objective, choice, fact, and reward state is keyed by
  player UUID in DGR SavedData and is shared across dimensions.
- NPC identity, entity/group selections, item identity, and installed package
  definitions are world data.
- Important mutations run on the server thread and validate permission and the
  current server-owned object before applying.

Unique NPC identity is stored as `npc_id -> NpcHostIdentity` in
`NpcIdentitySavedData`. It is not written to ordinary entity NBT or new CNPC
Stored Data. Death/unload does not free the reservation. Only explicit unbind
or transfer changes ownership.

Item IDs capture a normalized, count-independent ItemStack definition. Exact
groups reuse the same definition; fuzzy groups match only the registry name.

## Canonical graph contracts

Story and Session expose stable logic inputs and outputs. Their aggregate ports
use persisted `port_id` values, so display-name changes do not disconnect the
Project Story Graph. Removing a referenced boundary is a confirmed transaction.

Story Start owns one or more explicit start triggers. EnterStory is no longer a
new-authoring node; cross-Story activation is:

`Story A logic output -> Project Story Graph -> Story B logic input -> Story B Start`.

Condition owns one flow input, a logic expression, and named yes/no flow
outputs. One connected branch may wait for the matching value; two connected
branches select immediately.

Task has no flow graph and no Activate node. Objectives monitor events only
while all of their optional activation inputs are true, without losing existing
progress. A Task owns exactly one Settlement node; its ordered stable result
ports choose the first true result and emit exactly one aggregate flow output.
Task logic outputs never settle the Task.

## Story Packages and reload

Studio exports a deterministic directory package containing `manifest.json`,
the root Story, and every declared Actor, Item, Session, Task, membership, and
canonical resource.

Runtime scans the configured `darkgrey_rpg_story_packages` directory and
strictly validates manifest fields, paths, resource declarations, graph shapes,
and conflicts. Shared resources are accepted only when their declared source
bytes are identical. A failed scan retains the previous active package
snapshot. A successful replacement does not clear player SavedData.

## In-game tools

- Nominator writes entity/item identities through server-validated packets.
- Copier stores many sanitized templates. A copied entity inherits Groups but
  never a reserved unique NPC ID.
- Storage Box in Survival serializes and restores the same UUID while its NPC
  ID remains reserved. Restore fails closed if the reservation is missing or
  points to another UUID. Creative storage is an identity-free reusable
  template.
- Body and Editor are placeholder items only.

Entity templates are sanitized into explicit configuration, appearance,
attribute, equipment, AI, and extra sections. Runtime-only DGR identity keys,
position, motion, UUID, riding links, and unsafe transient state are not copied
into identity-free templates.

## Rewards and optional CNPC

`give_item` accepts `item_id` and `amount`, resolves an exact DGR
ItemStack definition on the server, and uses an idempotent per-player Story
receipt. Legacy stable actions remain available through their existing
compatibility path.

The CNPC adapter uses reflection and legacy Stored Data only as a fallback for
old projects. External DGR identity is authoritative. Registry/individual
identity and all selected Groups are routed in stable deduplicated order.
Third-party cloning cannot copy the external unique-ID registry entry.

Automatic identity migration for a CNPC resurrection that creates an unrelated
new UUID is deliberately fail-closed unless a stable compatibility key can be
proven. Explicit Nominator transfer remains the safe operation.

## Non-goals

This release does not provide a native NPC editor, arbitrary NBT actions,
general scripting/expressions, Task flow/concurrency/return nodes, CNPC
Quest/Dialogue migration, or a unified CNPC/DGR Journal.
