# Studio 2.1.2 Flow Connection Model

Studio 2.1.2 treats a connection as the logical tuple `from.output -> to`. The
same output may own at most one connection, while an input may accept multiple
incoming connections. The editor therefore distinguishes an output reconnect
from choosing one line in a multi-incoming fan.

## Gestures

- Drag an empty output to an input to create a connection.
- Drag an empty input to an output to create in the reverse gesture direction.
- Drag a connected output to replace or disconnect its one logical edge.
- Drag a single-incoming input to replace that connection's source.
- Use the explicit incoming-line handle when an input has multiple sources.
- Release an existing connection on blank canvas to disconnect it.
- Press `Esc`, lose capture, change DataContext, deactivate the window, or open
  a context menu to cancel the pointer session. Cancellation restores an
  existing connection instead of committing a partial edit.

Every create, replace, reconnect, or disconnect is one editor transaction and
therefore one Undo/Redo step. A reconnect never exposes an intermediate saved
state in which the old edge was removed but the new edge was not installed.

## Pointer and viewport boundary

Flow uses one `GraphPointerState` for node drag, wire drag, and middle-button
pan. These modes cannot overlap. Pan and cursor-centered zoom use shared graph
coordinate transforms; Fit All includes expanded node actual bounds and
supports negative coordinates.

The temporary wire uses the same solid visual language as a committed edge.
Ports remain visually and semantically distinct from property controls, so a
nearby node input cannot steal a drag that began on an output.

## Dynamic outputs

Dialogue Exit and Sequence edits are connection-aware. Renaming a connected
Dialogue Exit can migrate its edge, delete it after confirmation, or cancel.
Removing a connected Sequence step requires confirmation. Compatibility output
names from older PlayDialogue data are preserved on load and save.

## Validation, Problems, and Recovery

Validation issues carry Story, node, and field coordinates. Double-clicking a
Flow Problem opens or recenters the source node, expands the required section,
and focuses its mapped editor.

Dirty Flow resources are snapshotted atomically under
`resources/editor/recovery`. Invalid drafts are allowed there but never enter
Runtime project enumeration. Only a valid explicit save changes the official
Story JSON; a valid save or explicit discard clears its recovery draft.
